## 1. 目标与设计原则

| 原则 | 说明 |
| --- | --- |
| 单一容器 | 一个文件拿走全部内容，便于分享、备份、跨端迁移 |
| 自描述 | `manifest.json` 说清楚包里有什么、依赖什么、怎么读 |
| 可校验 | 每个文件带 SHA-256；导入前可离线完整校验 |
| 向前兼容 | 读取方必须忽略未知字段；扩展走 `extensions` 与 `x-` 前缀 |
| 不锁死用户 | 载荷为明文 JSON 与原始图片，第三方脚本可解析 |
| 不泄露隐私 | 绝不包含 API Key、绝对路径、设备标识 |
| 确定性 | 相同内容应产生字节一致的包（路径排序、固定时间戳） |

**扩展名**：`.stpack`　**MIME**：`application/vnd.smarttavern.package+zip`　**容器**：ZIP（deflate）

## 2. 目录结构

```
<name>.stpack
├─ manifest.json                 # 必需，必须位于根目录且为第一个条目
├─ data/
│  ├─ worlds.json                # WorldVersion[]（含 calendar / timeRhythm）
│  ├─ worldbooks.json            # WorldbookEntry[]
│  ├─ characters.json            # CharacterVersion[]（含 voice / visual）
│  ├─ promptPresets.json         # PromptPreset[]
│  ├─ rulepacks.json             # RulePack[]（仅用户自带 / 自定义的）
│  ├─ theme.json                 # Theme（kind: theme 时的载荷，见 §5）
│  ├─ session.json               # Session + SessionRefs（含 playerCharacter）
│  ├─ messages.jsonl             # 每行一条 Message（树形，含 parentId）
│  ├─ checkpoints.json           # Checkpoint[]（含 clock / deadlines）
│  ├─ agenda.json                # AgendaEntry[]
│  ├─ memories.json              # MemoryEntry[]（带 atMinute）
│  └─ state.json                 # 会话最终 SessionState（变量 / Sheet / 时钟）
├─ assets/
│  ├─ images/<sha256>.<ext>      # 原始图片，文件名即内容哈希
│  ├─ thumbs/<sha256>.webp       # 缩略图（可选）
│  └─ refs.json                  # 资源元数据与缩略图映射
├─ LICENSE.txt                   # 必需：包内容与内置规则包的许可声明
└─ README.txt                    # 必需：人类可读的包内容说明（可自动生成）
```

**路径规则**：一律使用 `/` 分隔；不得包含 `..`、绝对路径、驱动器号；
文件名仅允许 `[A-Za-z0-9._/-]`；所有文本文件为 UTF-8（无 BOM）。

**条目顺序**：ZIP 的**第 1 条固定为 `manifest.json`**（便于流式读取先取到清单），
其余条目按路径的 ASCII 字典序写入；所有条目使用固定时间戳 `1980-01-01`（详见 §11）。

**按包类型裁剪**：不需要的文件可省略（如世界包不含 `messages.jsonl`），
但 `manifest.json` 中 `contents.counts` 必须如实反映实际内容。

## 3. `manifest.json` 规范

### 3.1 字段

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `format` | `"smarttavern.package"` | ✅ | 固定字面量，用于识别 |
| `formatVersion` | integer | ✅ | **主版本号**，当前为 `1`。纯新增可选字段**不**提升此值（见 §8） |
| `kind` | enum | ✅ | `world` / `character` / `session` / `rulepack` / `prompt-preset` / `theme` / `bundle` |
| `id` | UUIDv7 | ✅ | 包自身的唯一标识 |
| `name` | string(1–200) | ✅ | 默认显示名 |
| `i18n.name` | `{locale: string}` | — | 多语言名称（如 `zh-CN` / `en`） |
| `description` | string(≤2000) | — | 简介 |
| `createdAt` | ISO 8601 UTC | ✅ | 导出时间 |
| `generator` | object | ✅ | `{app, version, platform}`，platform ∈ `web`/`desktop`/`mobile`/`cli` |
| `license` | string | ✅ | SPDX 标识符，或 `user-provided` / `mixed` |
| `source` | object | — | `{url?, author?, originalPackageId?, originalAuthor?}` |
| `tags` | string[] | — | 便于检索（题材、系统、语言等） |
| `schemaVersions` | `{entity: integer}` | ✅ | 各实体 schema 版本，供迁移判断。键为**固定枚举**：`world` / `worldbook` / `character` / `promptPreset` / `rulepack` / `theme` / `session` / `message` / `checkpoint` / `agenda` / `memory` / `asset` / `turn`；**必须包含包内实际出现的全部实体** |
| `refs` | Ref[] | — | 依赖的外部实体（见 §4） |
| `contents` | object | ✅ | `{counts, bytes}` 内容清单。`counts` 为**固定键集**：`worlds` / `worldbooks` / `characters` / `promptPresets` / `rulePacks` / `themes` / `sessions` / `messages` / `checkpoints` / `agenda` / `memories` / `assets`，未包含的类目写 `0`；`bytes` 为包内所有载荷与资源字节之和 |
| `entries` | Entry[] | ✅ | **除 manifest.json 外**所有文件的路径、大小、SHA-256 |
| `assets` | AssetMeta[] | — | 资源的尺寸、类型、缩略图映射 |
| `redaction` | object | ✅ | `{apiKeys:"excluded", absolutePaths:"excluded"}`，用于声明脱敏 |
| `signature` | null \| object | — | 预留（v1 固定为 `null`） |
| `extensions` | object | — | 扩展区，键名以 `x-` 开头 |

## 4. 引用、依赖与 ID

```ts
type Ref = {
  kind: 'world' | 'character' | 'rulepack' | 'prompt-preset' | 'asset';
  id: string;
  version?: number;
  requirement: 'embedded' | 'required' | 'optional';
  // embedded  = 内容已包含在本包中
  // required  = 导入方本地必须有，否则拒绝导入
  // optional  = 缺失时降级可用（如规则包）
};
```

- **实体 ID** 采用 UUIDv7（时间有序，便于排序与分片）。
- **会话包必须内嵌其引用的世界与角色版本**（`requirement: embedded`），
  保证"打开即可复现"，不依赖导入方是否拥有这些资产。
- **规则包不内嵌受版权保护内容**，只写 `optional` 引用并提示用户自行准备。

## 5. 包类型

| kind | 必需载荷 | 典型用途 |
| --- | --- | --- |
| `world` | `data/worlds.json` + 可选 `worldbooks.json` | 分享世界观与设定库 |
| `character` | `data/characters.json` + 可选 `assets/*`（立绘差分） | 分享角色卡（含视觉档案与配图） |
| `session` | `data/session.json` + `messages.jsonl` + `checkpoints.json` + `state.json` + **内嵌 world/characters** + 可选 `assets/*` | 完整存档：换设备继续、给别人接着玩 |
| `rulepack` | `data/rulepacks.json` | 分享规则包（**不得包含未授权规则全文**） |
| `prompt-preset` | `data/promptPresets.json` | 分享 Prompt 预设 |
| `theme` | `data/theme.json` + `assets/*` | 分享主题外观 |
| `bundle` | 上述任意组合 | 整套迁移 / 全库备份 |

**导出档位**（用户可选）：`仅设定`（world+character）/ `仅会话`（session+内嵌设定）/
`全量`（含所有资源）。UI 在导出前显示预估体积与内容清单。

## 6. 载荷规范

- 所有载荷为 `packages/schema` 定义的实体序列化结果，字段名与类型必须一致。
- `messages.jsonl`：每行一个 `Message`，**按 `createdAt` 升序；`createdAt` 相同者按 `id` 升序**
  （tie-break 写死：重生成 / swipe 常产生同毫秒消息，无 tie-break 则包顺序不确定）；树形关系靠 `parentId` 还原。
- `state.json`：会话最终 `SessionState`（含 `clock`、`innerClock`、`vars`、`sheets`、`deadlines`）。
- `checkpoints.json`：每个检查点自带完整 `state` 快照，读档不依赖回放消息。
- `assets/refs.json`：资源元数据（角色绑定、表情 / 服装标签、来源 prompt 与参数），
  用于重新生成或迁移到其他 Provider。
- 图片原文件不入库改格式：直接存原始字节，扩展名按真实 MIME 决定。

## 7. 导入流程与冲突处理

```
1. 解压到临时目录 → 检查 manifest 是否存在且可解析
2. formatVersion 兼容性检查（主版本必须 ≤ 本应用支持的主版本）
3. schema 校验：所有 data/*.json 通过 Zod 校验
4. 完整性校验：逐文件比对 entries[].sha256 与 bytes
5. 安全检查：路径穿越、文件数量与总大小上限、MIME 嗅探
6. 依赖检查：required 引用是否存在（缺则中止并列出缺什么）
7. 展示清单：几个世界 / 角色 / 消息 / 资源 + 占用空间 → 用户勾选要导入的部分
8. 写入：ID 冲突重映射，分批事务写入，写入前自动备份
9. 生成导入报告：重映射了哪些 ID、跳过了什么、是否有降级
```

**ID 冲突策略**

| 情况 | 处理 |
| --- | --- |
| 包内 ID 与本地已有 ID 相同、内容相同 | 复用本地实体，不重复创建 |
| 包内 ID 与本地已有 ID 相同、内容不同 | 生成新 ID，写入 `originId` 与 `importedFrom` |
| 包内引用指向被重映射的实体 | 同步重写引用，保证包内一致性 |

**导入报告**必须展示给用户（可折叠），这是"不静默覆盖"原则的落地方式。

## 8. 版本演进规则

| 变更类型 | 要求 |
| --- | --- |
| `formatVersion` 主版本 +1 | 破坏性变更（字段语义改变、必需文件移除）。旧读取方必须拒绝并提示升级 |
| 纯新增可选字段 | **不**提升 `formatVersion`。读取方必须忽略未知字段并正常导入；需要能力协商时写入 `extensions`（`x-` 前缀） |
| `schemaVersions[entity]` +1 | 单个实体结构变化；导入时按版本执行迁移函数 |
| 扩展 | 只允许写入 `extensions`（`x-` 前缀）或新增可选字段；不得复用已废弃字段名 |
| 废弃 | 先标记 `deprecated` 并保留至少一个大版本，再在下一个主版本移除 |

**迁移**：`packages/schema/migrations` 提供 `migrate(entity, fromVersion, toVersion)`，
导入时链式调用；每个迁移函数必须有前后 fixture 测试。

## 9. 校验与安全

- 必需文件缺失 / SHA-256 不匹配 / 大小不符 → **拒绝导入**并指出具体文件。
- ZIP 条目路径含 `..`、绝对路径、驱动器号、或符号链接 → **拒绝**。
- 单文件上限与总大小上限可配置（默认单文件 64 MB、总量 2 GB），超限需用户确认。
  这是**默认策略**，不是容器能力的上限：调用方可提高这两个值（`packages/packages` 的 `limits`），
  提高之后仍受下面 ZIP64 条款约束。二者不矛盾 —— 默认值管"我们默认愿意收多大"，ZIP64 管"格式能不能表达"。
- 路径**必须是 ASCII**（`[A-Za-z0-9._/-]`，见 §2）。ZIP 的 UTF-8 名称标志位照常设置以便互操作，
  但 v1 的有效包里它不产生任何非 ASCII 名称；读取方遇到非 ASCII 路径**拒绝**。
- JSON 解析设置深度与节点数上限，防止构造的恶意结构导致内存爆炸。
- 不执行包内任何脚本、模板或宏；宏只在用户导入后于本地渲染时展开。
- 图片仅按 MIME 嗅探处理；不解压嵌套压缩包。
- **ZIP64**：默认总量上限 2 GB，单文件亦可能超过经典 ZIP 的 4 GB 界限，
  因此实现必须支持读写 ZIP64 扩展字段，不得仅因体积直接失败。
- **确定性的边界**："相同内容产生相同字节"只在**同一实现内**成立——deflate 由具体 zlib 实现决定，
  不同语言 / 不同版本的压缩器产出的字节流可能不同。**跨实现的一致性以 `entries[].sha256`、
  `contents.counts` 与 `contents.bytes` 为准**，不得要求第三方实现产出逐字节相同的 ZIP。

## 10. 与 SillyTavern 的互操作

| SmartTavern | SillyTavern | 说明 |
| --- | --- | --- |
| `CharacterData` 基础字段 | 角色卡 V2/V3 JSON | 字段名一致，直接映射 |
| `CharacterData.voice/visual/sampling` | 无 | 写入 `extensions.smarttavern` |
| `WorldbookEntry` | World Info 条目 | 关键词、优先级、位置、深度可映射；时间条件为扩展 |
| `messages.jsonl` | `chat.jsonl` | 角色名 / 内容 / 时间戳可双向映射；树形结构在 ST 中退化为线性 |
| `PromptBlock[]` | Prompt Manager 预设 | 位置、深度、顺序可映射；自定义宏需降级说明 |
| `.stpack` | 无等价物 | 由本规范定义；导出会话时同时提供 `chat.jsonl` 选项 |

**导入 ST 资产**：解析后按本规范重新生成包内实体，不保留 ST 的原始 ID（重映射并记录来源）。
**导出到 ST**：只输出 ST 认识的字段；`extensions.smarttavern` 原样保留，保证可往返。

## 11. 实现要求

| 组件 | 职责 |
| --- | --- |
| `packages/schema` | 用 Zod 定义 manifest 与实体；导出 TS 类型、JSON Schema（`tools/` 脚本生成，提交到仓库） |
| `packages/packages` | 纯逻辑的打包 / 解包 / 校验，**不依赖 DOM 与具体存储**（可被第三方工具直接复用） |
| `packages/core/ports` | `PackageReader` / `PackageWriter` / `PackageValidator` 接口 |
| `tools/stpack-cli` | 命令行校验与查看：`validate <file>`、`inspect <file>`、`unpack <file> <dir>` |

**确定性打包要求**：`manifest.json` 固定为 ZIP 第 1 条，其余条目按路径的 ASCII 字典序写入；
所有条目使用固定时间戳（`1980-01-01`）；JSON 序列化使用稳定键序；
**同一实现下**相同内容必须产生相同字节（便于 diff 与哈希比对），跨实现的一致性以 `entries[].sha256` 为准（见 §9）。

**「稳定键序」的定义（v1-r3 明确）**：写入包的 JSON 一律使用 **canonical JSON**：

1. 对象键按 **ASCII 字典序递归排序**（嵌套对象同样处理）；
2. **数组保持原序**，绝不排序；
3. 不做美化（无缩进、无多余空格）；字符串按 JSON 标准转义，**非 ASCII 字符不转义**为 `\uXXXX`（保持 UTF-8 可读）；
4. 数字使用最短往返表示（与 `JSON.stringify` 的行为一致）。

这样两个不同实现只要内容相同，产出的载荷字节就相同，包与包之间可直接 diff。
条目级一致性仍以 `entries[].sha256` 为准（见 §9 的确定性边界）。

**阅读器的完整拒绝清单（v1-r4 补齐）**：§9 上文只点了路径穿越与符号链接，实现还必须拒绝

| 拒绝项 | 原因 |
| --- | --- |
| 加密条目 | 本格式不定义加密；遇到即为外来物 |
| 非 stored/deflate 的压缩方法 | 只支持这两种，其余无法保证确定性 |
| 多卷（分卷）归档 | 单文件即完整容器 |
| 条目注释、归档注释、数据描述符 | 我们的写入器从不产出；它们只扩大解析面 |
| 非普通条目（FIFO / 设备 / 目录项） | 超出"符号链接也要拒绝"的范围，同样拒绝 |
| 固定时间戳以外的时间戳（`unfixed-timestamp`） | §11 把字节一致性作为发布门槛，来源不明的 mtime 会破坏它；这是**读取拒绝**而不是警告 |
| 声明尺寸与实际不符、超出上限（zip bomb） | 解压时必须**中途截断**，不是解完再判断 |
| 版本需求 ≥ 45 却没有 ZIP64 扩展字段 | 自相矛盾的头 |

**不拒绝但跳过**：ZIP64 以外的扩展字段（向前兼容，见 §1）。**额外校验**：条目 CRC-32 也参与校验 ——
§9 只写了 SHA-256 与尺寸，但位翻转若发生在 deflate 流里，先由 CRC-32 指出，报错才具体。

**JSON Schema 发布**：生成的 JSON Schema 需随包一同发布（如 `schema/package-1.json`），
使第三方实现无需依赖本项目代码。
