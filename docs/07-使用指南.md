## 1. 这是什么

聪明酒馆（SmartTavern）是一个**本地优先**、多端、AI 辅助的**角色扮演与 TRPG 工作台**。用法是三段式：

**创建世界 → 创建角色 → 开始扮演。**

三条设计原则会直接影响你看到的行为：

- **本地优先。** 应用没有官方后端，也没有账号。你的世界、角色、会话、偏好和密钥都放在这台设备的浏览器数据库里；模型请求由浏览器直接发给你自己配置的服务（自带密钥，BYO-Key）。
- **兼容 SillyTavern 数据。** 角色卡字段名与 SillyTavern V2/V3 保持一致，世界书按它的概念映射，读进来的未知字段不会被丢掉。是「兼容它的数据格式」，不是「复刻它的引擎」。
- **数据契约先于界面。** 实体与包格式只在 `packages/schema` 定义一次，界面是它的一个视图。所以会出现这样的落差：某些数据在卡片和包里确实存在（例如自动推进时间的节奏字段、参考图引用），但界面上还没有编辑它的地方。本指南会把这些情况明确标出来。

> 当前仍是开发中的版本（M1 阶段），功能和界面都会变。

## 2. 安装与启动

**前置条件**

- **Node.js ≥ 22.12.0**（版本不够时安装会直接失败，而不是给个警告）。
- **pnpm**。请只用 pnpm 安装依赖，不要与 npm / yarn 混用（仓库的开发约定见 [CONTRIBUTING.md](../CONTRIBUTING.md)）。

**常用命令**（都在仓库根目录的 `package.json` 里定义）

| 目的 | 命令 |
| --- | --- |
| 安装依赖 | `pnpm install` |
| 启动开发服务器（改代码即时生效） | `pnpm dev` |
| 构建后再以 preview 方式预览构建产物 | `pnpm start` |
| 只构建 | `pnpm build` |
| 跑测试 | `pnpm test`（监听模式 `pnpm test:watch`） |
| 代码检查（含依赖方向与 i18n 硬编码文案两条专项检查） | `pnpm lint` |
| 类型检查 | `pnpm typecheck` |
| 一次跑完 lint + typecheck + test + build | `pnpm ci` |

`pnpm dev` 与 `pnpm start` 会在终端打印本地地址，用浏览器打开它即可；这两个命令只在本机提供服务。

**桌面壳（可选）**

桌面端**不是第二套界面**，它挂载的就是网页那份 UI，只是把 HTTP 能力换成由桌面运行环境承载。需要 Rust 工具链与 WebView2 运行时。

| 目的 | 命令 |
| --- | --- |
| 开发模式运行桌面窗口 | `pnpm --filter @smarttavern/desktop tauri:dev` |
| 只产出可执行文件 | `pnpm --filter @smarttavern/desktop tauri:build` |
| 格式 / clippy / Rust 测试 | `pnpm --filter @smarttavern/desktop tauri:check` |
| 完整安装包（msi / nsis） | `pnpm --filter @smarttavern/desktop tauri build` |

两个已经踩过的坑：完整打包需要联网下载打包工具；**debug 构建加载的是开发服务器地址**，直接双击产物目录里的 exe 只会得到白窗口，请用 `tauri:dev`。

## 3. 首次运行：语言与外观

**语言**

右上角有一个语言下拉，它一直在那里，不在设置页里。选项只有两个：**中文**、**English** —— 语言名用各自的语言书写，刻意不翻译。

- 默认是**中文**。
- 你还没选过语言时，应用会看浏览器偏好：只认 BCP-47 连字符标签，并按主语言标签匹配（`zh-Hans-CN`、`zh-TW` 都会落到中文；`en-US`、`en-GB` 落到英文）；认不出来的一律回落到中文。
- 选择会存进本机数据库，刷新和重开都保持。
- 切换语言是**立即生效**的界面级切换：界面文案跟着变，但已经写进数据的文本（例如你自己起的会话标题）不会跟着变。

**外观**

设置页最下面一节「外观」有三个控件，都是本机设置，马上生效：

- **主题**：跟随系统（默认）／亮色／暗色。「跟随系统」会跟随操作系统的深浅色变化实时切换。
- **字号**：按百分比缩放。
- **消息宽度**：按百分比控制消息栏宽度。

这三项和语言一样存在本机数据库里，与用户数据分开（见第 15 节）。

## 4. 首次运行：配置模型服务

设置页的「模型服务」一节是模型请求的唯一入口。要点是：**配置可以有多份，每份有自己的密钥。**

- 界面上不写死任何厂商，你填的是**服务地址（Base URL）**、**API Key**、**模型名**。地址必须是 `http(s)` URL。
- **本地服务（Ollama / vLLM 之类）可以把密钥留空**——应用明确允许空密钥。
- **模型名可以手填**，也可以点「获取模型列表」从服务端拉一份下拉列表。
  - 列表只显示前 200 个（聚合类服务的 `/models` 动辄上千条）；**这不限制你能配置什么**，输入框始终是自由文本。
  - 你当前保存的模型如果不在列表里，界面会**保留它并标记说明**，绝不会悄悄替你改掉它。原因是模型名被历史钉住（见下面「会话会钉住配置」），而且 `/models` 常常漏掉别名、微调版本和服务方自定义的 id。
- 「测试连接」成功时会显示 HTTP 状态码。**它只证明这个地址可达、`/models` 有响应**：它不校验模型名是否可用，不校验上下文预算，也不证明别的路径上没有浏览器 CORS 限制（见第 17 节）。

每一份配置的操作：

- **新增配置**：立即在数据库里生成一条配置（刷新后仍在），并成为新建会话时默认选用的那一份。
- **当前使用**：标记哪一份是默认；**新建会话会钉住当前选中的这一份**。
- **切换到这份配置**：改默认。
- **删除这份配置**：**如果还有会话钉着它，删除会被拒绝**，并告诉你被几个会话钉住、它们分别叫什么。你可以先去那些会话改用别的配置，再回来删。这不是刁难：会话的历史记录必须能说清「这段话是哪个服务、哪个模型产出的」，所以引用关系存在时配置不能凭空消失。

密钥本身的管理（明文 / 加密 / 解锁）是单独一节，见下一节。

## 5. 首次运行：密钥加密与解锁

**密钥存在哪里。** 密钥只写进**这台设备**的数据库里，不会进导出包、不会进日志、也不会进消息元数据。界面上明确写着：

> 本地 Ollama / vLLM 可以留空。密钥只保存在这台设备的数据库中。

**默认是明文。** 在设置页的「本地密钥加密」一节里，如果还没设置口令，界面会直接告诉你：

> 密钥目前以明文保存在本机数据库中。设置口令后将以 WebCrypto 加密存储。

**设置口令之后**，密钥以加密形式存放（口令至少 8 个字符），并进入以下两种状态之一：

- **锁定**：密钥已加密，当前标签页没有解锁。此时发请求会被拒绝，提示你解锁。
- **已解锁**：密钥已解密，**且只在这个标签页的内存里**；刷新页面后需要重新解锁。

几条需要记住的规则：

- **口令不会被保存**，刷新后要重新输入。
- **忘记口令就无法恢复密钥**——加密设计上不允许找回。此时唯一的做法是重新填写一次密钥（可以设新口令，也可以继续以明文保存）。
- **口令错误时存储内容不做任何修改**，所以你可以无限次重试，不会把密钥弄坏。
- 如果当前环境不支持 WebCrypto（例如页面不在安全上下文里），应用会明确告诉你「无法加密」，而不是假装保存成功。

**解锁对话框**在你真正需要密钥的时候出现（例如消息流上方的提示条上有一个「解锁」按钮）。输入口令即可继续；如果这条配置不是默认那一份，对话框还会标明它针对的是哪一份配置。

对话框里有一个默认关闭的选项：**「在这台设备上记住解锁」**。

> 只记住解锁后的密钥（不可导出的 WebCrypto 密钥），不保存口令；本设备的解锁可在「设置」里忘记。

也就是说：它记住的是**派生出来的、不可导出的密钥**，不是你的口令。勾选之后，刷新页面不需要再输口令；在设置里可以「忘记本设备的解锁」，忘记后密钥内容不变，你仍然可以用口令解锁。这条记录存放在一个**独立的数据库**里，与用户数据分开。

## 6. 世界卡与角色卡

### 6.1 新建与编辑

- **世界卡库**（顶部导航「世界」）与**角色卡库**（「角色」）各自有一张新建卡片：填一个名字就可以开始写。
- **世界卡**按分区编辑：基本 / 地区 / 势力 / 规则 / 叙事 / 历法与时间 / 时间节奏 / 开场。
- **角色卡**按分区编辑：SillyTavern 字段 / 发言档案 / 视觉档案 / 默认采样参数。
  - 其中「SillyTavern 字段」包括描述、性格、场景、开场白、对话示例、创作者注记、系统提示、历史后指令、备选开场白、标签、创作者、卡片版本等。界面自己说明：**这些字段名与 SillyTavern V2/V3 保持一致**。
  - **角色卡上不保存「玩家 / 卡司」标记**——身份由会话决定，同一张卡可以在一个会话里当玩家角色、在另一个会话里当配角。

**历法是数据，不是常量。** 世界卡的历法可以完全自定义：一天几小时、一小时几分钟都可以不是 24/60；时段允许跨过午夜（结束小时小于起始小时是合法的）；起始时刻可以是负数（从历法纪元起的分钟数）。

### 6.2 草稿与版本（最容易误解的一点）

这是本应用最需要先理解的一条规则：

> **自动保存只写草稿；点「发布新版本」才会生成新的版本。**

- 你在编辑器里看到的改动都会即时存成本地草稿，关掉页面回来还在。
- **草稿不是版本**。草稿基于某个版本（界面会写「草稿基于 v2」之类），发布后成为下一个版本（「已发布 v3」）。
- **已发布的版本不可变**，也正因为如此，历史会话才说得清自己当时用的是哪一版。
- 界面上写着这句提示，值得读一遍：

> 编辑的是草稿：自动保存只写草稿，点「发布新版本」才会生成新的版本。

- **离开编辑器不会提交任何东西**：草稿还在，已发布的版本还是原来那些。
- **放弃草稿**是一个真实动作：它删除这份草稿，编辑器回退到已发布版本。
- 发布前会做校验。有校验问题时发布会**被拒绝**（提示「存在校验问题，未发布新版本」），并列出问题所在字段；**此时不会产生新版本**。
- 草稿是**半成品**，所以它本身不要求完整（名字空着也算中途状态），缺的字段会被补全成默认值；已发布的版本则必须是完整合法的。

### 6.3 自定义字段

世界卡与角色卡都可以加自定义字段：

> 自定义字段保存在卡片数据的 customFields 里，字段名就是键，所以改名等于删除后重新添加。

字段名不能为空，也不能与已有字段重名。请把这一点当作命名约定来用：**先想好名字再写**。

### 6.4 视觉档案与参考图

角色卡的「视觉档案」保存外貌（发色发型、瞳色、体型、肤色、显著特征）、服装差分与表情差分（各带标识与提示词）、画风预设与采样参数。

**参考图目前只保存资源 ID。** 界面自己写着：

> 资源管线尚未实现：参考图只保存 assetId，可能指向不存在的资源。

也就是说：现在可以记录「这张卡参考了哪张图」，但应用还不管理图片本身，也不会把它渲染出来。

## 7. 创建会话

「新建会话」页把一次开局需要钉住的东西一次选完。**身份属于会话，不属于角色卡**，所以同一张卡可以在不同会话里扮演不同身份。

表单从上到下是：

1. **世界卡**（必选）与**世界版本**。默认取最新版本，界面会明说：「本次会话固定 v3（该世界最新版本为 v4）。」——**这一步就把版本钉死**，之后世界卡再发新版本也不会影响这个会话。
2. **参与的角色卡**（至少勾一张）。
3. **玩家角色**（你操控的那一张，必选）。其余勾选的卡自动成为**卡司**，由 AI 扮演。界面会实时显示推导出的卡司；只勾了一张卡时会提示「卡司为空：本次只有你扮演的角色登场」。
4. **提示预设与规则包**。这里要如实说明现状：
   > 目前只有内置预设：还不能新建或导入预设，所以这里没有可选项。
   > 尚未提供规则包，本次会话不绑定规则包。
5. **初始时钟**：按「自历法纪元起的分钟数」填写，默认是所选世界版本的起始时刻；**留空就用默认值**，必须是整数分钟。

点「创建会话」后进入扮演界面。创建失败时会明确告诉你「创建失败，没有写入会话」。

**模型是第一次发言时才记录的。** 会话创建时，这条会话记录的模型信息是一个占位值；**真正产出内容的 provider 与模型，在你第一次成功生成时写进会话**。这样做的目的是让历史可信：转录上标注的模型就是实际产出它的那个。采样参数目前由应用默认给出，选择采样参数的界面还没有提供。

## 8. 扮演界面：开场、时钟、消息流

### 8.1 开场

会话还没有第一条消息时，界面会出现「开场」面板，给你三种方式（**一旦写下就不能再重选**）：

- **写开场**：自己写下第一条（内容为空会被拒绝）。
- **AI 生成开场**：让模型写。
- **跳过开场**：直接自己发第一条消息。

开场是消息链的第一条消息，所以这个面板只在链为空时出现。

### 8.2 世界时钟

界面顶部会显示当前世界时间（日期，可能带当前时段名）。时间推进**目前只有手动这一种**：

- **+1 时段**：按这个世界自己的时段边界前进（时段可以跨午夜）。
- **+1 小时**、**+1 天**。
- **自定义（分钟）**：填整数，可以是负数（例如 `-30` 往回调）。推进后会回显「已推进 90 分钟：……」之类的结果；非整数会被拒绝。

时钟是会话状态的一部分，因此**会随存档点一起回滚**（见第 10 节）。

### 8.3 消息流

每条消息下面有这些操作：

- **继续写**：让模型接着当前内容写下去（只能在角色发言之后续写；没有可续写内容时会提示）。
- **重新生成**：**同一个提问生成另一条回答**，于是这一轮会有多条回答。界面会显示「第 1 / 3 条」并用上一条 / 下一条切换——**这些都是同一父节点的兄弟分支，切分支不会删掉另一条**。
- **编辑**：改这条消息的内容，保存或取消。编辑不会把旁白改标成对白（消息的呈现类型会保留）。
- **删除**：**只有链尾的消息能删。** 如果这条消息后面还有内容，删除会被**拒绝**，并提示你先删除它之后的消息——这是有意的：不做级联删除，避免一次点击抹掉一大段历史。删除是两步确认。

底部的输入框用来写你的行动或台词；发送后可以「停止」正在进行的生成。

## 9. 状态栏与变量

「状态栏」就是会话级的一组自由变量：文本、数值、布尔三种类型。界面写着：

> 会话级自由变量：`{{getvar}}` 读取它，`{{setvar}}` 赋值、`{{addvar}}` 做增量；布尔值写 true 或 false。

需要知道的三件事：

- 变量是**会话级、扁平**的，没有 SillyTavern 那种全局 / 角色 / 会话的多级查找链——因为目前唯一的写入者是你，隐藏的解析顺序只会让「为什么读到的不是我写的那条」变得无法回答。
- 数值只接受有限数（空白**不是** 0，是拒绝）；布尔只接受 `true` / `false`；文本可以是空串。
- **`setvar` 是赋值，`addvar` 是增量**：写进转录的是算好的绝对值，所以回看历史时看到的就是当时的值。

变量属于会话状态，**会随存档点一起回滚**。让 AI 自己写状态或关系（例如自动更新好感度）**尚未提供**。

## 10. 定点存档、读档与分叉

### 10.1 存档点

「定点存档」面板里给存档点起个名字（例如「进城前」）并保存。界面写着它记下了什么：

> 存档会记下当前的消息位置、时钟、变量与卡司状态。读档会把会话整体回滚到那一刻：不会删除任何消息，也不会改变世界、角色与预设的绑定。

具体到行为：

- **读档是一次整体回滚**：时钟、场景、变量、卡司状态一起回到那一刻，不会出现「时钟回到了存档、变量还是现在的」这种半吊子状态。
- **读档不删消息。** 存档点之后的消息原地保留，它们只是不再处于当前分支上；你随时可以再读回后来的存档，或者切回先前的分支。
- **读档不改绑定**：世界版本、角色卡版本、预设的钉住关系都不动。存档点记的是「场景里的一个位置」，不是「另一套内容」。
- 读档与删除都是**两步确认**。删除一个存档点是幂等的，多点一次不会报错。
- 也允许存一个「还没有任何消息」的档（回到空链）。

### 10.2 分叉

分叉会**新建一个会话**：

> 分叉会新建一个会话：它带着所选位置的消息、时钟、变量与卡司状态，以及此前存档点的副本；原会话完全不受影响，其中的引用也全部指向新会话自己的消息。

- 分叉的位置有两种：**在当前进度分叉**，或者**从此存档分叉**。
- 新会话标题会带一个「（分叉）」后缀（标题在你分叉时所用的界面语言下写成，之后就固定了）。
- 那些「消息没有跟着过来」的存档点不会复制到新时间线——它们在新的时间线上没有位置。
- 如果一个存档点已经被删除，或者它属于别的会话，分叉会被拒绝并说明原因。

## 11. AI 共创

「AI 共创」面板让你和模型讨论一张卡，而**模型只能提案，不能直接改你的数据**：

> 与 AI 讨论这张世界卡：它每次回答都会给出一份补丁提案，采纳与否由你决定。

流程是四步：

1. **说**：在面板里输入你的要求。
2. **预览**：「实时预览」显示的是**采纳这份提案之后卡片的样子**——预览用的就是要写进草稿的那份数据，不是另算一份。
3. **采纳 / 否决**：采纳写进草稿（注意：是**草稿**，仍然要再点「发布新版本」才会成为版本），否决则什么都不发生。
4. **撤销这次采纳**：把草稿恢复成采纳之前的样子。

它会拒绝做这几类事，而且拒绝时**草稿不变**：

- 提案会让卡片不合法（例如必填字段被清空）——显示成「这份提案会让卡片不合法（…），没有应用」。
- 提案里的某个操作无法应用——**整份提案都不应用**，不做一半。
- 模型返回的内容不是可解析的提案、缺字段、含非法操作、或一次给出太多改动——面板会把模型的原话附上供你判断。
- 提案动到了本次请求不该动的字段——**整份提案作废**。

**生成模式**适合从零写一张卡：

> 让 AI 按步骤把这张卡写出来：每个步骤单独请求一次，你逐步骤采纳或否决，草稿随之逐步长出来。

每个步骤会显示「第 2 / 6 步」和状态（待生成 / 已采纳 / 已否决 / 已跳过），你可以「生成下一步」「跳过这一步」「停止生成」。

**字段级 AI 操作**：选一个字段，让 AI **只改这一个字段**——重写 / 扩写 / 精简。动到别处的提案会被直接拒绝。

**发言档案评估**：依据角色卡已有的内容（描述、性格、场景、开场白等）评估发言欲望、能力、条数上限、冷却这些参数，并给出评估理由；可以选择「依据哪个世界生成」，也可以不指定世界。如果卡片内容太少，它会**在本地就拒绝**，不发请求。

使用共创前必须先在设置里配好模型服务，否则会提示：

> 还没有配置模型服务，无法开始共创：请先在设置里填写服务地址与模型名。

## 12. 卡司干预与发言调度

### 12.1 发言调度

调度是**本地**做的，模型不能突破：

> 本地调度器按发言欲望与能力给出顺序，并强制执行硬上限：每轮最多 3 人发言，单人条数与冷却轮数由角色卡决定，模型无法突破。

- **每轮最多 3 人发言**，这是调度器的固定上限（不是存储设置，界面上没有地方改它）。
- **单人条数上限**（1–5）与**冷却轮数**（0–3）写在**角色卡的发言档案**里，按角色生效。
- 面板会直接告诉你「下一位发言：某某（发言欲望 70 / 发言能力 50，在可选角色里最高）」，或者「本轮没有人可以发言」。
- 需要理由时它也是明说的。一个角色不能被选中，界面会给出原因之一：单轮条数已达上限、冷却中（还要等几轮）、本轮发言人数已达上限、绑定的角色卡版本已不在库中、不在本次会话的卡司里、已被你移出场景、已被你禁言。

**手动指派**优先于本地打分：在卡司列表里「指派」某个角色，TA 就会排到你指定的位置。

> 目前没有「时间/调度」的总开关；时间推进只能手动（见第 8.2 节），自动推进的字段虽然存在于卡片数据里，但**尚未接线**。见第 19 节。

### 12.2 卡司干预

对任一卡司角色可以：

- **禁言 / 解除禁言**：TA 仍然在场，但调度器不会再选中 TA 发言。
- **移出场景 / 恢复出场**：TA 不参与本轮，调度器不会再选中 TA。
- **撤销这次干预**：把卡司状态恢复到干预之前。

两种干预都是**两步确认**，并且界面说清了它的性质：

> 禁言与移出场景只影响调度，不改角色卡：被禁言或移出场景的角色不会被选为下一位发言者。这是会话的实时状态，会随存档点一起回滚；改错了可以撤销。

### 12.3 编辑 AI 的发言

「编辑」可以直接改任何一条已写下的 AI 发言并保存（也可以取消）。它只是改这条消息的内容，不会改变「谁说的」和「是什么类型的发言」。想换一种走向，通常更好的做法是「重新生成」拿到另一条分支，或者「继续写」把场景接下去。

## 13. 内容包：导出、导入与示例

顶部导航的「内容包」页是导出、导入和示例内容的**唯一入口**：

> 把当前的库导出成一个 .stpack 文件，或者从文件、内置示例导入。导入会先给出报告，确认之后才写入。

### 13.1 导出整个库

「导出内容包」会把：

> 库里每个世界和角色的最新版本（连同世界书条目）打包成一个 .stpack 文件。

浏览器会下载这个文件。库里还没有世界或角色时，按钮会禁用并提示没有可导出的内容。

### 13.2 导入：先报告，再确认

选择一个 `.stpack` 文件后，**解析后先显示报告，确认才会写入**：

> 选择一个 .stpack 文件。解析后先显示报告，确认才会写入；被拒绝的导入不会改动任何数据。

- 报告标题是「导入报告（尚未写入）」，里面列出包名与格式版本、以及逐条实体的处理结果：**新增 / 复用 / 改名 / 跳过**，并给出「报告与提示」。
- 实体类别可能包括：世界、世界书条目、角色、提示预设、会话、消息、存档点、日程、记忆——**具体出现哪些取决于这个包**。
- 确认后写入，再显示「导入结果」；此时你还能一键「打开世界库 / 打开角色库」去看刚写进去的内容。
- **包无法导入时，库不会发生任何改动**，报告会说明原因。

### 13.3 内置示例内容包

「导入示例内容包」会导入一份内置示例（**长日港 · 末班渡**），走的是**与你选文件时完全相同的一条导入路径**。界面上解释了为什么应用内需要这个入口：

> 内置示例「长日港 · 末班渡」在进程内构建，并走与你所选文件完全相同的一条导入路径。命令行的 stpack 写入的是 JSON 文件库，与浏览器应用使用的 IndexedDB 不是同一个库，所以应用内需要这个入口。

**请特别注意这一点：命令行工具 `stpack import` 写的是一个 JSON 文件库，而应用用的是浏览器数据库，两者不是同一个库。** 也就是说，用命令行导入内容**不会**把内容放进应用里；要在应用里得到内容，就用这一页的「选择文件…」或「导入示例内容包」。

导入示例后，如果这个包建议了搭配方式，会出现「**用示例开局**」按钮：按示例包建议的搭配（长日港，扮演沈砚）用刚导入的行新建一个会话，走的也是应用自己的创建流程。

## 14. SillyTavern 兼容性

先把结论放在前面，因为它和很多人的预期不同：

> **数据层的兼容已经实现（并有测试覆盖），但应用界面里现在还没有「导入 / 导出 SillyTavern 文件」的按钮；命令行工具也没有这条命令。**

也就是说，下面描述的能力**当前只能通过代码（库层 API）使用**，不能在界面上点出来。这一点在第 19 节再次列出。

**已经实现的映射**

- **角色卡 JSON** ⇄ 应用的角色卡数据：读 SillyTavern V1/V2/V3 卡，也能写回。
- **角色卡 PNG**：SillyTavern 的角色卡就是一张普通 PNG，卡片 JSON 经 base64 放在名为 `chara` 的 `tEXt` 块里。
  - 读的时候优先用 `ccv3` 块（V3 卡更完整），没有再退回 `chara`，并会报告用的是哪一个；`zTXt` / `iTXt` 形式的 `chara` **不解码**（本包不带解压器），而是报告出来，不去猜。
  - 写 V3 卡时会同时写 `chara` 与 `ccv3`，两者内容一致（不允许出现两份会互相矛盾的兼容副本）。
  - **导出一张 PNG 必须给底图。** 项目目前没有资源管线（没有生图器、没有缩略图、卡片也没有存头像），所以「写一张 PNG」要么是凭空造像素，要么是写一张空图假装成功——后者更糟。因此导出需要显式传入源图；**没有底图时不产出任何字节**，只报一个「需要底图」的结果。给了底图时，**除卡片块之外的每一个块都按字节原样保留**，不会重新编码一个像素。
- **世界书**：同时读两种写法——独立的 `world_info` 文件（条目按 `uid` 编号）与 V2/V3 卡片里的 `character_book`（条目是数组，字段名不同）。字段映射包括关键词、内容、优先级、插入位置、深度、概率、启用状态与备注。
  - 插入位置在两边词汇之间是可逆映射；被折叠的情况会保留原始的 ST 值，所以**没人改过的条目写回去时一模一样**。
  - **没有归宿的未知字段不会被丢掉**：它们原样保存在条目里，导入报告会用一条「无归宿字段」的提示逐条点名，导出时再写回去。这包括次级关键词、常量、大小写敏感、分组、粘性 / 冷却 / 延迟、向量化等。**世界书自身的容器字段**（书名、描述、扫描深度、令牌预算等）在我们的数据模型里没有对应实体，所以它们会随条目一起返回，导出时要原样传回去。
  - 已知的两处**语义**缺口（会被报告，不会被粉饰）：SillyTavern 的 `constant: true`（「永远注入、忽略关键词」）在我们的条目上没有对应开关，导入后会像普通条目一样按关键词匹配；反过来，我们的 `conditions`（时段、起始分钟、天数范围）在 SillyTavern 里没有写法，导出后会变成无条件注入。**值都还在，变的是行为。**

**字段直通。** 上面这些映射遵循同一条规则：应用模型认识的字段按文档映射；**不认识的字段原样保留并报告**；模型认识、但类型不可用的字段会用文档默认值替换并报告。

## 15. 数据存在哪里

- **浏览器数据库（IndexedDB）**，库名是 `smarttavern`。它按**站点**隔离：换一个地址访问、换一个浏览器、换一台设备，都是另一个空库。
- 因此：**清空站点数据 / 换浏览器 = 数据没了**。要搬到别处，唯一的手段是**导出内容包再导入**（见第 13 节）。应用没有官方同步服务，也没有云备份。
- **集合的概念**：数据库里按集合存放不同种类的行——世界、世界版本、角色、角色版本、世界书、世界书条目、提示预设、规则包、会话、消息、存档点、日程、轮次计划、记忆、资源、任务、服务配置、设置、迁移。界面目前实际用到的是其中的一部分（世界与版本、角色与版本、会话、消息、存档点、轮次计划、设置，以及包里的世界书条目）；日程、记忆、资源、任务、规则包、提示预设这些集合已经定义好，但还没有界面在用。
- **设置行**里放的是本机偏好与草稿：语言、主题、字号、消息宽度、模型服务配置（每份一行）、默认使用哪一份、以及世界卡和角色卡的**草稿**。所以「草稿」和「用户数据」在同一库里，但它们是不同形状的行。
- **密钥的加密行与用户数据在一起**（就在那份模型服务配置的行里），而**「在这台设备上记住解锁」的记录放在另一个独立的数据库里**——它是设备上的一次性便利，不是内容的一部分；在设置里「忘记本设备的解锁」就能撤销它，而密钥内容不变。

## 16. 命令行工具 stpack

仓库里有一个命令行工具，用来看、验证、拆开、导入和**生成** `.stpack` 包。命令名与参数如下（在仓库根目录用 `pnpm stpack -- <参数>` 调用）：

| 命令 | 作用 |
| --- | --- |
| `stpack validate <file>` | 检查一个包；不可导入时以退出码 1 结束 |
| `stpack inspect <file>` | 打印清单摘要与内容列表 |
| `stpack unpack <file> <dir>` | 把包解到目录（先写清单） |
| `stpack import <file> <lib>` | 导入到一个 **JSON 文件库**并打印报告 |
| `stpack example <file>` | 生成内置示例内容包 |

选项：`--json`（机器可读输出）、`--force`（`unpack` 覆盖已有文件，`example` 覆盖已有 `.stpack`）、`--dry-run`（`import` 只报告不写入）、`--select a,b`（`import` 只选这些类别，例如 `worlds,characters`，可重复或用逗号分隔）、`-h` / `--help`。

退出码：`0` 成功；`1` 包不合法或导入被拒；`2` 用法错误；`3` 读写失败。

**必须记住的一点：`stpack import` 的目标是一个 JSON 文件库，不是应用使用的浏览器数据库。** 它适合做命令行下的批量检查、转换和脚本化处理；**在命令行导入的内容不会出现在应用界面里**。

## 17. 常见问题

**为什么提示密钥被锁定？**
这条配置的密钥已经加密，而当前标签页还没有解锁。点提示里的「解锁」并输入口令即可继续。口令不会被保存，刷新后要重新输入；如果你在解锁对话框里勾了「在这台设备上记住解锁」，刷新后就不需要再输口令了。

**口令忘了怎么办？**
无法恢复。加密设计上不提供找回，只能在设置里重新填写一次密钥。

**「测试连接」成功了，为什么共创或生成还是失败？**
「测试连接」只证明服务地址可达、`/models` 有响应。它不校验：模型名是否真的可用、上下文预算是否够、以及别的请求路径上是否存在浏览器 CORS 限制。请逐条排除：这条配置是否处于**已解锁**状态（锁定时发请求会被拒绝）；模型名是否与服务的实际可用名称一致（服务端拒绝请求时会提示检查模型名）；请求是否超出模型上下文预算（这种情况会带着说明被拒绝，不会发出去）；服务是否对别的路径做了浏览器来源限制。

**为什么我又选同一个 `.stpack` 文件也能重新导入？**
文件选择框在每次选择后都会被重置，所以重复选同一个文件（例如你重新导出了一版）依然会触发解析与新的报告。

**导入被拒绝了，我的库会变吗？**
不会。「被拒绝的导入不会改动任何数据」，界面上也会这么说。

**为什么这条消息删不掉？**
因为它后面还有内容。删除只对链尾生效，不做级联删除。想改历史的话，用「编辑」，或者从更早的存档点读档 / 分叉。

**读档会把后面的消息删掉吗？**
不会。读档只是把「当前在哪个位置」和会话状态整体回滚，消息行原样留着；你可以再读回后来的存档，或者切回另一条分支。

**分叉会影响原来的会话吗？**
不会。分叉只写新行，原会话完全不受影响，包括它自己的引用关系。

**为什么某份模型服务配置删不掉？**
还有会话钉着它。提示里会告诉你被几个会话钉住、分别是哪些。先去那些会话改用别的配置，再删。

**为什么我改了卡片，版本号没变？**
因为自动保存只写**草稿**。点「发布新版本」才会产生新版本。

**能直接输入网址打开某一页吗？**
不能。应用用的是内存路由，地址栏里没有可分享的页面地址；请通过界面导航（顶部导航与各页面的返回链接）。

## 18. 开发者：本地验证与约定

**一次跑完 CI 的五个步骤**

```
pnpm ci:local
```

它按 `lockfile → lint → typecheck → test → build` 的顺序执行，任何一步失败就停下，并打印汇总。也可以只跑子集：

```
pnpm ci:local lint test
```

`pnpm ci:local` 与 `pnpm ci` 等价（`pnpm ci` 就是 lint + typecheck + test + build），区别只在本地跑法上。

**依赖方向**（唯一允许的方向，由脚本真实遍历 import 图强制）

```
packages/schema ← packages/core ← {providers, storage, rules, packages, importers} ← apps/*
```

- `packages/schema` 不依赖任何内部包；实体与包格式类型只能从这里导入。
- `packages/core` 不碰 DOM / 浏览器 API，也不导入具体实现，只通过端口注入。
- 适配器层之间互不导入；`tools/*` 是叶子。
- 检查命令：`pnpm check:deps`（`pnpm lint` 里已经包含）。

**i18n 规则**

- **界面文案必须写进目录，不许在界面代码里硬编码中文。** 文案的唯一真相源是 `packages/i18n/src/catalog.ts` 的 `zh-CN`，其他语言以它为类型基准，漏译会直接编译报错。
- 检查命令：`pnpm check:i18n`（`pnpm lint` 里已经包含）。它用 TypeScript 编译器扫描界面代码，抓中日韩字符的字面量与 JSX 文本，以及 `title` / `placeholder` / `aria-label` / `aria-description` / `alt` 这类属性上的裸字符串。文案该待的地方（`packages/i18n`）、测试与夹具是豁免的。
- 语言名用各自语言书写（中文 / English），刻意不翻译。
- 边界：界面文案与**模型提示词**是两件事，后者不是 UI 文案；开发日志写英文。

## 19. 本指南未覆盖 / 待补

以下是**当前版本里还没有**的能力。写在这里是为了让你不必去界面里反复找：

- **提示预设的编辑器**：现在只能用内置预设，不能新建或导入预设。
- **规则包**：会话模板里没有可绑定的规则包；骰点、检定与检索属于规则层，尚未提供。
- **世界书的编辑界面**：世界书条目能随内容包导入导出，但应用里还没有编辑它们的页面。
- **资源（图片）管线**：参考图只保存资源 ID，可能指向不存在的资源；没有生图流程，生图相关的 Provider / 模型 / 采样器字段只是数据。
- **记忆与日程**：存储里已经留了集合，界面还没有用它们的地方。
- **让 AI 自己写状态或关系**（例如自动更新变量、好感度）。
- **SillyTavern 文件的导入 / 导出入口**：映射层已实现并有测试（第 14 节），但界面与命令行都没有暴露这条操作。
- **「时间与调度」的应用级开关**：已经在决策记录里定下（默认关闭），但**尚未实现**。所以现在既没有开关，也没有自动推进；时间是手动推进的。
- **主题包**：外观目前只有主题 / 字号 / 消息宽度三个本机设置，没有可导入导出的主题包。
- **多语言**：只有中文与 English 两种界面语言。
- 桌面端的打包与发布细节（安装包签名、更新机制）不在本指南范围内。
- 桌面端在部分受限环境中无法启动窗口，这是已知问题，与本指南的使用说明无关。
