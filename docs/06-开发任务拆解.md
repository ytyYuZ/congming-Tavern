## 0. 工程约定（零号任务，先做完再碰业务代码）

### 0.1 仓库与工具链

| 项 | 选择 |
| --- | --- |
| 包管理 | pnpm workspaces（可选 Turborepo 做任务编排） |
| 语言 | TypeScript（`strict: true`，`noUncheckedIndexedAccess: true`） |
| 构建 | Vite（apps/web）、Tauri CLI（apps/desktop） |
| Lint / Format | Biome（一个工具搞定，配置最少） |
| 测试 | Vitest（单元 / 集成）、Playwright（e2e）、msw（Provider mock） |
| 文档站 | VitePress（`docs/` 直接作为内容源） |
| CI | GitHub Actions：`lint → typecheck → test → build`，四项全绿才能合并 |

### 0.2 依赖方向（用 lint 规则强制）

```
packages/schema  ←  packages/core  ←  {providers, storage, rules, packages, importers}  ←  apps/*
```

- `core` 禁止 import DOM API（`window` / `document` / `localStorage`）与任何具体 Provider。
- `schema` 禁止依赖任何其他内部包。
- 违反以上任一条 → CI 失败。

### 0.3 代码约定

- 命名：文件 `kebab-case.ts`，类型 `PascalCase`，函数与变量 `camelCase`，常量 `SCREAMING_SNAKE`。
- 所有实体类型**只能**从 `packages/schema` 导入，禁止在各模块重复定义。
- 纯函数优先：Prompt 装配、评分、时间计算、骰子解析都必须是可单测的纯函数。
- 不写"以后可能用得上"的抽象；抽象只在出现第二个实现时提取。
- 提交信息用 Conventional Commits（`feat:` / `fix:` / `docs:` / `refactor:` / `test:`）。
- 每个 PR 必须包含测试；纯 UI 调整可用 e2e 覆盖。
- **输出一律只追加，绝不原地重绘**：CLI、构建脚本与界面都不得使用 spinner、原地刷新的进度条
  或 ANSI 清屏序列（`\r`、`ESC[2K`、`ESC[1A`）。宿主终端与 WebView 会因此持续闪烁，
  这是**产品级要求**而非审美偏好 —— 进度用追加的日志行表达。
  `tools/stpack-cli` 有一条测试断言输出不含 `\u001b` 与 `\r`；`apps/*` 的构建脚本用 `vite build --logLevel warn`
  —— Vite 默认的 info 级输出会发 `ESC[2K` 清行重绘，`--logLevel warn` 是实测唯一
  ESC 与 CR 都为零、且仍保留警告与错误的选项（`CI=1` 无效，`--silent` 仍含 CR）。

### 0.4 完成定义（DoD）

一个任务算完成，当且仅当：功能实现 + 单测/集成测试通过 + 类型检查通过 + lint 通过 +
相关文档更新 + 在 `apps/web` 中可手动验证（纯后端任务除外）。

## 6. 关键路径与并行建议

```
M0-T0 ──▶ M0-T1 ──▶ M0-T2 ──┬─▶ M0-T3 ──▶ M0-T4 ─▶ M1-M3
                             └─▶ M0-T5 ──┬─▶ M0-T6 ─▶ M1-G3
                                          ├─▶ M0-T7 ─▶ M0-T8 ─▶ M1-S2
                                          └─▶ M0-T9
M0-T5 ──▶ M1-G4 ──┬─▶ M1-W2 ──▶ M1-W3 ──▶ M1-C2
                   ├─▶ M1-T3
                   └─▶ M2-P1
```

- **串行不可省**：T0 → T1 → T2 → T3/T5。契约与包格式是所有后续工作的地基。

### 8.2 M0-T3 打包 / 解包 / 校验（约 1.5 人日，本期最贵）

**产出**（`packages/packages/src/`）

- `zip/write.ts`、`zip/read.ts`：窄范围 ZIP 容器（**已定：自研**，见 ADR-018）
- `canonical-json.ts`：稳定键序序列化（**已定：递归 ASCII 字典序**，见 ADR-018 与 `docs/04` §11）
- `manifest.ts`：构建与校验 manifest，计算 `entries[].sha256` 与 `contents`
- `pack.ts`、`unpack.ts`、`validate.ts`：纯函数式入口
- `limits.ts`：单文件 64 MB / 总量 2 GB / 条目数上限 / JSON 深度与节点数上限（`docs/04` §9）
- 单测：`docs/04` §12 第 1–7 条逐条对应；外加 zip-slip、符号链接、zip bomb、加密条目、伪造 MIME 的拒绝用例

**已定**

1. 只支持 **stored(0) 与 deflate(8)**、无加密、不解压嵌套压缩包；其余一律拒绝并指出具体条目。
2. 压缩走平台 **`CompressionStream('deflate-raw')`**，以保证零依赖且 Node 与浏览器同源（Node 侧可用 `zlib.deflateRawSync` 兜底，收敛在一个函数里）。
3. 写入顺序：第 1 条固定 `manifest.json`，其余按路径 ASCII 字典序；DOS 时间戳固定 `1980-01-01 00:00:00`。
4. `unpack` 只落盘字节，**绝不执行**包内任何内容；路径穿越（`..` / 绝对路径 / 盘符 / 符号链接）一律拒绝。

**验收**：同实现下 `pack → unpack → pack` 字节一致；篡改任一字节即校验失败并指出文件；恶意 ZIP 全部被拒。

| 6 | 旧 `schemaVersions` → 迁移正确执行 |
| 7 | 含 `../` 的恶意 ZIP → 拒绝 |

### 10.2 刻意不做的事（连同理由，免得下次当成"漏了"）

- **`innerClock`（战斗轮/回合）**：折算需要会话的 `secondsPerRound` 与一个明确的"战斗结束"信号，

- **`advance_time` 策略与 `timeRhythm` 隐式推进**：这是"谁可以推进时间"的策略，只能在审批 UI
  所在之处执行 —— **纯函数没法问人**。`advance(step)` 因此是 policy-free 的。
- **副作用链第 4/6/7 步**（世界书重估、自动存档、prompt 注入）：I/O 与装配，而 core 不做 I/O。
  第 1/2/3/5 步的值已实现为纯函数，等编排者串起来。
- **宏 `{{roll}}` / `{{random}}` / `{{pick}}`**：骰子引擎属于 M3-R1，而"没有来源的随机数"不该由
  core 拥有。它们与任何不认识的宏**原样保留并计入 `unresolvedMacros`** —— 少一个展开器必须在输出里
  看得见，不能悄悄替换成空字符串。
- **`display()` 返回结构化部件**而不是成品句子（ADR-030）：月名与时段名是**内容**，
  连接词才是**文案**；引擎一旦拼句子就等于拥有了 locale，而 core 连 `packages/i18n` 都不许 import。
  唯一的字符串形式 `renderParts` 是纯数据 join。
- **时钟目前读 `Session.initialClock`**：实时时间应在 `SessionState.clock`，而 `sessionStates` 行是
  M1-T4/M1-M1 的事。读取收在 `clockOf()` **一处**，所以那次替换是改一个函数而不是改每个调用点。

### 10.3 M1-S6 变量系统：契约在哪里（**先读 schema，再动手**）

我第一次写这一节时说"数据契约至今不存在"——**那句话不准确，而且错得危险**：它会让人以为要凭空
设计一套变量系统，而实际上 `packages/schema` 的 `SessionStateSchema` **已经冻结了大部分契约**，
只是没有任何一处把它**当作变量契约说出来**。具体分工如下（结论见 **ADR-031**）：

| 问题 | 答案现在在哪 |
| --- | --- |
| 变量挂在哪、`getvar` 的查找顺序 | **schema 已冻结**：`SessionState.vars` 一张扁平表 → 会话作用域，没有查找链。世界/角色的值是**创建会话时种下的初始值**（M1-S1），此后一个真相源 |
| 能不能存对象 / 数组 | **schema 已冻结**：只有 `string \| number \| boolean`。复杂结构走 `sheets`（那里 `unknown` 是刻意的：schema 归规则包所有） |
| 与存档、时钟回滚的关系 | **schema 已冻结**：变量属于**一份** `SessionState` 快照，checkpoint 整份快照它 → M1-S6 与 M1-T4、M1-M1 是**同一次写入**，不是三条线 |
| `setvar` 是赋值还是增量 | **ADR-031 已定**：`setvar` 赋值，增量另起 `addvar`。不接受 `{{setvar::hp::+3}}`——它与字面量 `"+3"` 无法区分 |
| M1 里谁能改变量 | **ADR-031 已定**：只有人（状态栏）。AI 的 `update_state` / `update_relation` 是 M2+ 的通道，但"将来会有机器写入"决定了写入必须走**纯函数**（ADR-010） |
| 未定义变量怎么读 | **ADR-031 已定**：原样保留并进 `unresolvedMacros`，不替换成空串（与 M1-G4 同一条规则） |

因此这一项不再"卡在设计"：剩下的实现是 `macros.ts` 的 `setvar`/`addvar`/`getvar`、
`chat/clock.ts` 的 `variables` 入参改为 `SessionState.vars`，以及状态栏本身（依赖 M1-S1）。
在状态栏落地之前，composer 侧的 `variables` / `variableChanges` **保持现状**——它们是预留的接缝。
