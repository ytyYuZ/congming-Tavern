## 0. 工程约定（零号任务，先做完再碰业务代码）

### 0.1 仓库与工具链

| 项 | 选择 |
| --- | --- |
| 包管理 | pnpm workspaces（可选 Turborepo 做任务编排） |
| 语言 | TypeScript（`strict: true`，`noUncheckedIndexedAccess: true`） |
| 构建 | Vite（apps/web）、Tauri CLI（apps/desktop） |
| Lint / Format | Biome（一个工具搞定，配置最少） |
| 测试 | Vitest（单元 / 集成）、Playwright（e2e）、msw（Provider mock） |
| 文档站 | VitePress（`docs/` 直接作为内容源） |
| CI | GitHub Actions：`lint → typecheck → test → build`，四项全绿才能合并 |

### 0.2 依赖方向（用 lint 规则强制）

```
packages/schema  ←  packages/core  ←  {providers, storage, rules, packages, importers}  ←  apps/*
```

- `core` 禁止 import DOM API（`window` / `document` / `localStorage`）与任何具体 Provider。
- `schema` 禁止依赖任何其他内部包。
- 违反以上任一条 → CI 失败。

### 0.3 代码约定

- 命名：文件 `kebab-case.ts`，类型 `PascalCase`，函数与变量 `camelCase`，常量 `SCREAMING_SNAKE`。
- 所有实体类型**只能**从 `packages/schema` 导入，禁止在各模块重复定义。
- 纯函数优先：Prompt 装配、评分、时间计算、骰子解析都必须是可单测的纯函数。
- 不写"以后可能用得上"的抽象；抽象只在出现第二个实现时提取。
- 提交信息用 Conventional Commits（`feat:` / `fix:` / `docs:` / `refactor:` / `test:`）。
- 每个 PR 必须包含测试；纯 UI 调整可用 e2e 覆盖。

### 0.4 完成定义（DoD）

一个任务算完成，当且仅当：功能实现 + 单测/集成测试通过 + 类型检查通过 + lint 通过 +
相关文档更新 + 在 `apps/web` 中可手动验证（纯后端任务除外）。

## 6. 关键路径与并行建议

```
M0-T0 ──▶ M0-T1 ──▶ M0-T2 ──┬─▶ M0-T3 ──▶ M0-T4 ─▶ M1-M3
                             └─▶ M0-T5 ──┬─▶ M0-T6 ─▶ M1-G3
                                          ├─▶ M0-T7 ─▶ M0-T8 ─▶ M1-S2
                                          └─▶ M0-T9
M0-T5 ──▶ M1-G4 ──┬─▶ M1-W2 ──▶ M1-W3 ──▶ M1-C2
                   ├─▶ M1-T3
                   └─▶ M2-P1
```

- **串行不可省**：T0 → T1 → T2 → T3/T5。契约与包格式是所有后续工作的地基。
- **可并行**：UI 侧（M1-G1/G2）与 Provider 侧（M0-T6）互不阻塞；
  时间系统（M1-T1）与调度（M1-S5）相互独立；生图（M2-I*）与记忆（M2-P*）可分两条线。
- **必须尽早**：M1-M3（包导出导入）——它是验证数据模型是否正确的唯一手段，不要拖到最后。

### 8.1 M0-T2 包格式 schema（约 0.5 人日）

**产出**

- `packages/schema/src/package.ts`：`PackageManifest`（`docs/04` §3.1 全字段）、`PackageEntry`、`PackageRef`、`PackageAssetRef`、`PackageKind`、`GeneratorInfo`、`RedactionInfo`、`PackageContents`
- `packages/schema/src/migrations/index.ts`：`migrate(entity, fromVersion, toVersion)` 骨架 + 空迁移表（`docs/04` §8）
- `tools/schema-export/export.mjs`：导出 `schema/package-1.json`

> **本期不做**：`entities/promptPreset.ts`（`PromptPreset` / `PromptBlock`）。已拍板延后到 M1，
> 后果与缓解见 §8.5 决定 1 与 §8.6。
- 单测：manifest 正例 / 最小例 / 缺字段表 / 越界枚举 / 未知字段剥除 / 往返稳定 / `formatVersion: 2` 被拒

**已定的设计决定**（有异议请直接说）

1. **导出位置**：仓库根 `schema/package-1.json`（与 `docs/04` §11 的写法一致）。`schema/` 是新目录，需在 `README.md` 的文档索引里登记。
2. **draft 版本**：JSON Schema **2020-12**，并把 `$schema` 显式写入产物。
3. **版本拒绝的位置**：schema 内只接受字面量 `formatVersion: 1`；"主版本高于本实现"由读取方在解析前拒绝（`docs/04` §7 第 2 步），不塞进 schema。
4. **`signature`**：v1 固定 `z.null()`（预留位）。
5. **`schemaVersions` / `contents.counts`**：使用 r2 定下的固定键集，缺项**必须写 0**，不得省略键。
6. **`extensions`**：与实体同一套规则（键 `x-` 前缀、值必须 JSON、未知字段剥除）。

**验收**：`pnpm ci:local` 四项全绿；`schema/package-1.json` 由脚本生成并提交（禁止手写第二份）；自建示例包 manifest 通过校验。

### 8.2 M0-T3 打包 / 解包 / 校验（约 1.5 人日，本期最贵）

**产出**（`packages/packages/src/`）

- `zip/write.ts`、`zip/read.ts`：窄范围 ZIP 容器（**已定：自研**，见 ADR-018）
- `canonical-json.ts`：稳定键序序列化（**已定：递归 ASCII 字典序**，见 ADR-018 与 `docs/04` §11）
- `manifest.ts`：构建与校验 manifest，计算 `entries[].sha256` 与 `contents`
- `pack.ts`、`unpack.ts`、`validate.ts`：纯函数式入口
- `limits.ts`：单文件 64 MB / 总量 2 GB / 条目数上限 / JSON 深度与节点数上限（`docs/04` §9）
- 单测：`docs/04` §12 第 1–7 条逐条对应；外加 zip-slip、符号链接、zip bomb、加密条目、伪造 MIME 的拒绝用例

**已定**

1. 只支持 **stored(0) 与 deflate(8)**、无加密、不解压嵌套压缩包；其余一律拒绝并指出具体条目。
2. 压缩走平台 **`CompressionStream('deflate-raw')`**，以保证零依赖且 Node 与浏览器同源（Node 侧可用 `zlib.deflateRawSync` 兜底，收敛在一个函数里）。
3. 写入顺序：第 1 条固定 `manifest.json`，其余按路径 ASCII 字典序；DOS 时间戳固定 `1980-01-01 00:00:00`。
4. `unpack` 只落盘字节，**绝不执行**包内任何内容；路径穿越（`..` / 绝对路径 / 盘符 / 符号链接）一律拒绝。

**验收**：同实现下 `pack → unpack → pack` 字节一致；篡改任一字节即校验失败并指出文件；恶意 ZIP 全部被拒。

### 8.3 M0-T4 包 CLI（约 0.5 人日）

**产出**（`tools/stpack-cli/src/`）：入口 + `commands/{validate,inspect,unpack}.ts`。

- `validate <file>`：退出码 0/1，逐项打印校验结果与失败原因
- `inspect <file>`：manifest 摘要 + 内容清单（世界 / 角色 / 消息 / 资源数与体积）
- `unpack <file> <dir>`：安全解包，保留 `manifest.json`

**已定**：参数解析用 Node 内置 `node:util` 的 `parseArgs`（零依赖）；输出默认人类可读，`--json` 给机器可读，便于 CI 断言退出码与字段。

**验收**：三个子命令可用；`inspect` 输出内容清单；非法包的退出码与提示稳定可预测。

### 8.4 M0-T5 核心接口（约 1 人日）

**产出**（`packages/core/src/ports/`）

- `llm.ts`：`LLMProvider`、`ChatRequest`、`StreamEvent`（6 种事件）、`ModelInfo`、`ProviderCapabilities`
- `image.ts`：`ImageProvider`、`ImageJob`、`ImageJobStatus`
- `storage.ts`：`StorageAdapter`、`Tx`，以及集合名与索引的常量表
- `assets.ts`：`AssetStore`
- `package.ts`：`PackageReader` / `PackageWriter` / `PackageValidator`
- `tools.ts`：`ToolRuntime`（`docs/02` §5.3，契约 #8）—— 工具签名（名称 / 描述 / JSON Schema 参数）、
  `ToolCallResult`、领域校验钩子、**三级降级协议**（原生 function calling → 结构化输出 → 文本协议），
  以及"AI 只能请求、执行权在本地"的审批结果类型
- `mock/`：每个 port 的测试替身（§1 表 M0-T5 的验收要求"有 mock 实现用于测试"）

**已定**

1. 集合名与索引**逐字对齐 `docs/02` §7**，并集中成常量对象，避免字符串散落在各处。
2. `core/ports` 只放接口与常量，**零实现**；实现分别在 `providers/`、`storage/`、`packages/`。
3. `StreamEvent.error` 带 `retryable`；四种错误映射（鉴权 / 限流 / 网络 / 内容审核）在 M0-T6 落实。
4. **`tools.ts` 只冻结"签名 + 降级协议 + 审批结果"，不实现任何具体工具**；`docs/02` §5.3 那 15 个内置工具属 M1–M3。
5. 工具的参数校验复用 M0-T2 的 Zod → JSON Schema 管线，因此 M0-T5 一并产出 `schema/tools-1.json`
   （CLI、UI 表单与将来的插件工具声明都读它）。

**验收**：接口完整、有 mock 覆盖、M0-T6/T7 可直接实现；`packages/core` 仍然不含 DOM。
