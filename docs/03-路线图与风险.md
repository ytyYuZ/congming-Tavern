## 1. 里程碑

工作量以"人日"粗估，假设 1 名开发者 + AI 辅助；实际偏差可能 ±50%，仅用于排序而非承诺。

### M0 · 契约冻结与骨架验证（5–8 人日）

**目标**：把最贵、最难改的东西先钉死，并验证最不确定的技术点。

- **`packages/schema` 冻结**：实体 Zod 定义 + JSON Schema 导出（对应架构文档第 13 节的 8 项契约）
- **包格式 v1 实现**：`packages/packages` 打包 / 解包 / 校验 + `tools/stpack-cli`；
  通过 `docs/04-分享格式规范.md` 第 12 节前 7 条测试
- `packages/core` 骨架 + `LLMProvider` 接口 + 1 个 OpenAI 兼容实现
- 最小链路：配置密钥 → 发消息 → 流式渲染 → 落 IndexedDB → 重启仍在
- Tauri 2 桌面壳能打包运行，Rust 侧 HTTP 直连可用
- ~~决策点：Svelte vs React~~ → **已定：React 19**（ADR-017）
- ~~决策点：Tauri vs Electron~~ → **已定：Tauri 2**（ADR-002 不变）。Rust 工具链需在 M0-T8 前安装，
  当前环境**未安装 `cargo`/`rustc`**；若安装受阻则兜底 Electron（需新增 ADR 取代 ADR-002 的桌面部分，
  `packages/*` 与 `apps/web` 无需改动）

**验收**：包往返**同一实现下**字节一致（跨实现一致性以 `entries[].sha256` 为准）；桌面端连续对话 20 轮，重启后数据完好。

### M1 · MVP：三阶段跑通（25–35 人日）

**目标**：新用户从零到第一场扮演，全程无需编辑配置文件。

- 通用：i18n 骨架、主题、设置页、Provider 配置页
- 世界：结构化卡片编辑 + AI 共创对话 + 补丁提案 + 随机/有限指示生成 + **历法设定**
- 角色：**统一角色卡**编辑 + AI 生成 + **发言档案编辑与 AI 自动评估** + 视觉档案
- 扮演：会话创建 + **指定玩家角色** + 引入 + 流式/swipe/编辑 + **用户干预卡司**
- 调度：**基础版**（用户手动指派顺序、每轮人数与单人条数上限）
- 时间：**基础版**（世界时钟常驻显示、手动推进、时钟入存档、时间注入上下文）
- 存档：定点存档 + 分叉 + **按包格式导出/导入**（世界包、角色包、会话包）
- 兼容：SillyTavern 角色卡与世界书导入导出（往返无损）
- 教程：首次向导 + 内置示例内容包 + 帮助面板

**验收**：PRD 第 9 节第 1–13、17、18 条通过。

### M2 · 记忆、图像与时间（20–25 人日）

- Prompt 引擎完善（块管理 UI、宏面板、token 预算可视化、Prompt 调试面板）
- 世界书编辑器 + 关键词/时间条件触发 + 命中解释
- 滚动摘要 + 结构化记忆条目（含时间戳）
- 变量系统 + 状态栏
- **调度完整版**：三种模式、欲望/能力评分、调度面板与理由展示
- **时间完整版**：隐式推进、AI 请求推进策略、日程表、倒计时、时间轴视图
- 视觉档案 + 立绘 / 颜绘 / 差分生成 + 差分矩阵 + 任务队列 + 资源库
- 扮演中按情绪自动切换颜绘

**验收**：100 轮对话中 AI 仍能引用第 5 轮的关键设定；为角色生成 1 立绘 + 8 差分；
推进 30 天后日程与倒计时行为正确；调度模式下每轮发言者与理由可解释。

### M3 · TRPG 规则（15–20 人日）

- 骰子引擎 + 判定引擎 + 骰点历史（含世界时钟戳）
- 规则包运行时与 schema 校验 + 导入
- 内置开放许可规则包（D&D 5e SRD、通用 d20 / d100）
- 角色卡 Sheet（按规则包模板）
- 规则速查（本地全文检索 + 分类浏览 + 收藏 + 注入上下文）
- 随机表 + AI 主持模式（骰点回灌、规则引用）
- **跑团轮次时钟**：战斗轮与叙事时钟分离、状态持续时间

**验收**：用 COC 7e 规则包完成一次带 3 次判定的短团，所有骰点可追溯。

### M4 · 增强（持续）

- 移动端布局打磨、PWA 优化、Tauri 移动端壳
- 时间线树可视化、记忆向量检索、旁白/导演模式、会话内搜索
- 战斗轮追踪、插件机制（宏 / 工具 / 规则包 / 生图工作流）
- 可选同步（WebDAV / 自建服务端）、包的合并语义
- 文档站、图文教程、社区分享渠道

## 2. 迭代节奏建议

- 每 1–2 周一次可运行版本，优先保证"主流程永远可用"。
- 每个里程碑结束做一次**真实用户测试**（1 个新手 + 1 个 SillyTavern 老用户）。
- **数据契约先于界面**：schema 与包格式的返工成本远高于 UI 返工成本。
- 每个里程碑结束导出一次 `.stpack` 并做导入回归，及早暴露数据模型缺陷。
- 时间系统与调度器的行为用"表驱动测试"锁住（给定状态 → 期望输出），便于后续调参。

## 4. 合规与法律

- **SillyTavern**：AGPL-3.0。本项目**不复制其代码**，仅做格式兼容；同时本项目自身采用
  AGPL-3.0，与上游生态一致，将来若需要参考或移植其实现也不再有许可证边界问题。
- **规则内容**：D&D 5e SRD 为 CC-BY-4.0（可再分发，需署名）；CoC 7e、Cyberpunk RED、
  Fabula Ultima 的免费材料通常仅限个人使用，**不得打包进本项目**。规则包必须携带
  `license` 与 `source`，UI 必须展示。
- **AI 生成图像**：不同 Provider 对商用、二次分发、训练数据的条款差异大；
  UI 提示用户查看所选 Provider 条款，包内保留生成参数以便溯源。
- **用户导入内容**：角色卡可能含受版权保护的设定，责任归属用户；应用提供来源记录与删除能力。
- **隐私**：本地优先架构本身即最有效的合规手段；若未来做遥测，必须默认关闭、可关闭、
  且不记录对话内容。
- **内容分级**：默认为关闭 / 不提供敏感内容策略，由本地开关控制；包格式中不携带分级内容标记，
  避免在分享环节引入审核责任。

## 5. 原开放问题与决议

| # | 问题 | 决议 |
| --- | --- | --- |
| 1 | 产品正式名称 | **仍待定**（工作区名 `SmartTavern` 可能与既有项目重名，发布前确定） |
| 2 | 分享格式标准何时定 | **先行冻结**：`docs/04-分享格式规范.md` v1，M0 即实现 |
| 3 | 世界书与结构化记忆是否合并 | **保留两套机制**（关键词/条件触发 vs 语义抽取），**共用编辑器与存储层** |
| 4 | 多角色发言调度权归谁 | **可配置三模式**（用户全权 / 自定义规则 / AI 决定）；默认"用户全权 + 规则辅助"；角色按发言欲望与发言能力评分排序 |
| 5 | 时间与日程是否要做 | **要做且提高优先级**：基础部分进 MVP（M1），完整部分进 M2 |
| 6 | 存档包的"合并"语义 | 暂不做，留待 M4（当前只支持导入为独立实体） |
| 7 | 是否公开发布到应用商店 | 待定，不影响架构（仅影响签名分发与 NSFW 策略） |

## 6. 补充建议清单（已采纳）

以下 20 条建议已全部纳入文档，标注其落地位置。

**架构与工程**

1. 把引擎做成 headless 的 `core` 包 → 架构 §1、§3
2. 一切 AI 产出走「提案 → 确认」→ 原则 P3、架构 §5.3
3. 不可变版本 + 血缘 → PRD §5.5、架构 §4
4. 引入 ToolRuntime 用结构化调用操作状态 → 架构 §5.3
5. 先冻结 8 项契约再写 UI → 架构 §13、任务拆解 M0-T1~T8
6. 数据格式先行（包格式 v1 + 实体 schema）→ `docs/04-分享格式规范.md`

**体验与产品**

7. 黄金路径优先（5 分钟从零到第一轮）→ 原则 P1、验收标准 1–3
8. 导入即获客（ST 角色卡/世界书/预设无损往返）→ F9
9. 高质量示例内容包 + 引导式教程 → F8-1、F8-2
10. Prompt 调试面板 → 架构 §12
11. 移动端先做响应式 PWA → D3

**AI 与内容**

12. 骰点由本地引擎产生并回填 → F7-2、架构 §5.4
13. 生图一致性最省成本路线（固定种子 + 固定 base prompt）→ D6、架构 §5.5
14. 模型分工与成本控制 → F1-6、架构 §12
15. AI 抽取 + 用户确认的世界书与记忆 → F5-5、架构 §5.2
16. 内容分级做成统一策略层 → F10-4、架构 §10

**长期**

17. 插件点（宏 / 工具 / 规则包 / 生图工作流）→ 架构 §5.1、§5.3、§9
18. 同步与协作后置但预留（以 `.stpack` 为最小协作单元）→ F10-6、M4

**本轮新增**

19. **时间必须显式建模**（唯一真值 + 历法映射 + 入存档）→ D11、F11、架构 §5.7
20. **发言调度必须参数化且本地计算**（欲望/能力评分 + 硬约束 + 可解释）→ D10、F3-4、F4-10、架构 §5.6
