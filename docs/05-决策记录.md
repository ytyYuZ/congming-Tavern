## ADR-001 · 不 fork SillyTavern，只兼容其数据格式

- 状态：已定
- 决策：自建前端；兼容角色卡 V2/V3、世界书、Prompt 预设、`chat.jsonl`；可选把 ST 后端作为一个 Provider
- 理由：ST 前端是无框架大型单页，UI 重构成本高于重写体验层；上游迭代快，fork 后长期跟进成本高
- 影响：F9、架构 D1；需自研 Prompt 引擎
- 详见：`docs/02-技术架构.md` D1

## ADR-002 · 多端形态与优先级

- 状态：已定
- 决策：Web/PWA 一等公民 → 桌面（Tauri 2）→ 移动（响应式 PWA 优先）
- 理由：一套 UI 代码覆盖三端；避免过早承担原生构建链成本
- 影响：F10、D3、R2

## ADR-003 · 不做后端，BYO-Key + 可选轻量代理

- 状态：已定
- 决策：默认前端直连 Provider；提供可选自建代理解决 Web 端 CORS 与密钥暴露；不做官方云服务
- 理由：隐私、成本、去中心化；本地优先是核心卖点
- 影响：F1-1、F10-2、D5

## ADR-004 · 存储：IndexedDB 先行，SQLite 后补

- 状态：已定
- 决策：`StorageAdapter` 抽象；MVP 全端用 Dexie/IndexedDB；V1 为桌面端增加 SQLite 实现
- 理由：先求"一套代码全平台"，避免双实现拖慢 MVP；资源走独立 AssetStore，迁移只拷目录
- 影响：D4、架构 §7

## ADR-005 · 前端框架

- 状态：已定 → **已被 ADR-017 取代**（前端框架改为 React 19）。本条保留作历史记录，不再作为实现依据
- 决策：Svelte 5 + TypeScript + Vite + Tailwind；UI 与业务状态分离
- 理由：细粒度响应式适合消息流 + 立绘 + 状态栏的高频局部更新；体积小
- 影响：D2、架构 §3

## ADR-006 · 开源许可证

- 状态：已定
- 决策：项目**完全开源**，采用 **AGPL-3.0**
- 理由：与 SillyTavern 生态一致，彻底消除许可证边界风险；保证衍生改进回流社区
- 备选：若希望被宽松地商用集成，可在首次公开发布前改为 Apache-2.0（之后更改需全体贡献者同意）
- 影响：R5、合规章节

## ADR-007 · 规则内容版权边界

- 状态：已定
- 决策：只内置开放许可内容（D&D 5e SRD、通用 d20/d100 模板）；其余靠用户导入；包内必须带 `license`/`source`
- 理由：避免侵权；把责任边界写清楚
- 影响：F7-1、D7、R4

## ADR-008 · 内容分级

- 状态：已定
- 决策：**默认关闭 / 不提供**敏感内容策略；由本地开关控制（关闭 / 本地过滤 / 交给 Provider 过滤）
- 理由：面向通用分发渠道合规；把策略权交给用户
- 影响：F10-4、R10

## ADR-009 · 分享格式先行冻结

- 状态：已定
- 决策：`.stpack` v1 作为第一个实现的模块；唯一事实来源是 `packages/schema` 的 Zod 定义
- 理由：存档、分享、备份、跨端迁移、第三方互操作全依赖它；晚定会引发全量返工
- 影响：`docs/04-分享格式规范.md`、M0、R16

## ADR-010 · 角色卡统一，身份是会话的属性

- 状态：已定
- 决策：角色卡不再区分玩家 / 卡司；`Session.refs.playerCharacter` 在扮演开始时指定玩家角色，其余为卡司
- 理由：一张卡应在不同会话中扮演不同身份；避免重复建卡与导入导出映射；用户干预能力对所有卡一致
- 影响：F3-1、F4-2、架构 D9；移除 `personas` 集合与 `kind` 字段

## ADR-011 · 发言调度由本地计算并参数化

- 状态：已定
- 决策：角色卡带发言档案（欲望 / 能力 / 标签 / 条数上限 / 冷却）；本地评分排序 + 硬约束；
  三种模式（用户全权 / 自定义规则 / AI 决定）；AI 只能提顺序提案
- 理由：把"谁说话"从玄学变可调参数；可解释、可复现、可防止抢戏与冷场
- 影响：F3-4、F3-5、F4-6、F4-10、架构 §5.6、R14

## ADR-012 · 时间显式建模并进入存档

- 状态：已定
- 决策：`WorldClock`（纪元分钟数为唯一真值 + 历法映射）；时间随 Checkpoint 回滚；
  世界书支持时间条件；AI 只能请求推进
- 理由：时间是长线扮演与 TRPG 战役的骨架；事后补几乎等于重构存档与记忆
- 影响：F11、F5-3、F7-8、架构 §5.7、D11、R15

## ADR-013 · 骰点本地权威

- 状态：已定
- 决策：骰子与判定由本地引擎执行，结果回灌给 AI；禁止 AI 自行编造骰值
- 理由：TRPG 可信度底线
- 影响：F7-2、F7-7、架构 §5.4

## ADR-014 · 生图一致性采用分级策略

- 状态：已定
- 决策：L1 固定种子 + 固定 base prompt（首发）→ L2 参考图 img2img → L3 控制网/Reference → L4 专属 LoRA
- 理由：L1 覆盖多数颜绘需求且零额外依赖，避免一开始就背上重型管线
- 影响：F6、架构 §5.5、D6、R6

## ADR-015 · 世界书与结构化记忆保留两套机制

- 状态：已定
- 决策：世界书（关键词 / 时间条件触发）与结构化记忆（AI 抽取 + 用户确认）各自独立，
  **共用同一个编辑器与存储层**
- 理由：两者的触发语义不同（确定性命中 vs 语义抽取），强行合并会两头不讨好
- 影响：F5-2、F5-5、架构 §5.2

## ADR-016 · 数据契约集中在 `packages/schema`

- 状态：已定
- 决策：所有实体与包格式的 Zod 定义集中一处，导出 TS 类型与 JSON Schema；禁止模块私自定义类型
- 理由：防止 schema 漂移导致的全代码返工；JSON Schema 可对外发布供第三方实现
- 影响：架构 §3、§13、R17

## ADR-017 · 前端框架改用 React 19（**取代 ADR-005**）

- 状态：已定（2026-09-26 追加）。本条取代 ADR-005；ADR-005 原文保留作历史记录，不再作为实现依据
- 决策：前端框架定为 **React 19 + TypeScript + Vite**。配套选型：
  TanStack Router（路由）、Zustand + Dexie liveQuery（UI 状态与数据订阅）、
  `react-hook-form` + `@hookform/resolvers/zod`（表单）、Tailwind CSS v4 + Radix Primitives（样式与无障碍）、
  TanStack Virtual（消息树等长列表虚拟化）、dnd-kit（发言顺序 / 议程排序）、
  react-i18next（i18n）、Vitest + Testing Library（测试）
- 理由：① 本项目 UI 主体是"Zod 驱动的结构化表单 + 长列表 + 拖拽排序"，
  React 生态在这些方向有成熟且互为配套的方案，手写胶水最少；
  ② `packages/schema` 以 Zod 为唯一事实来源，React 侧有与 Zod 直连的表单方案；
  ③ 本地优先、无 SSR/SEO 诉求，Vite + SPA 已足够；
  ④ 代码生成与维护的确定性更高，UI 返工成本在本项目中最高
- 代价：打包体积大于 Svelte（非本项目瓶颈）；需接受 React 生态较快的依赖更新节奏
- 影响：D2、架构 §1 §3、`docs/03` 里程碑决策点、`docs/06` M0 决策点、`README` 技术栈速览
- 备注：ADR-005 原本就写明"若团队更熟 React 可切换"，本次切换正是该条款的落地
