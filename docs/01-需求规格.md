## 1. 背景与目标

### 1.1 产品定位

SmartTavern 是一个**本地优先、多端运行、AI 辅助的一站式角色扮演（Roleplay / TRPG）工作台**。
它以《最终物语》（Fabula Ultima）式的「创建世界 → 创建角色 → 开始扮演」三段式结构组织
完整使用流程，兼容 SillyTavern 的角色卡、世界书、Prompt 预设等生态数据格式，并把
AI 生图（立绘 / 颜绘 / 差分）、TRPG 规则速查与判定、时间与日程推进、定点存档与时间线迭代
纳入同一条工作流。

一句话：**让一个没接触过 AI 跑团的人，5 分钟内完成「从零到第一轮对话」。**

### 1.2 要解决的问题

| 现状痛点 | SmartTavern 的回应 |
| --- | --- |
| SillyTavern 功能强大但配置项多，新手上手门槛高 | 三段式向导、内置教程、开箱即用的示例内容包 |
| 世界观 / 角色 / 对话散落在不同工具里 | 同一工作台完成创建、扮演、复盘、迭代 |
| 扮演过程缺乏"存档点"和"时间线"概念 | 自动存档 + 定点快照 + 回溯分叉 + 存档包导出 |
| 立绘 / 表情差分需要在画图工具里手工维护 | 角色视觉档案 + 一键生成与差分 + 按情绪自动切换 |
| 跑团时翻规则书打断沉浸感 | 规则包 + 本地速查 + 骰子/判定引擎 + AI 引用规则 |
| AI 容易遗忘设定、随意改动设定 | 世界书 + 分层记忆 + 结构化工具调用 + 变更提案确认 |
| 多角色场景下 AI 轮次混乱、有人抢话有人沉默 | **发言调度器**：按发言欲望 / 发言能力排序，模式可切换 |
| 时间流逝靠模型随口说，前后矛盾 | **世界时钟 + 日程表**：时间可推进、可回溯、可触发事件 |

### 1.3 非目标（明确不做，用于控制范围）

- 不做在线多人实时联机跑团（V1 之前不做；通过共享存档包实现异步协作）
- 不做模型训练 / 微调平台（只支持把已有 LoRA / Embedding 作为生成参数引用）
- 不做内容分发市场与社区平台（V2 之后再评估）
- **不内置受版权保护的商业规则全文**（见 `docs/03-路线图与风险.md` 合规章节）
- 不做云端账号体系与服务器侧数据存储（本地优先；同步为可选的自建方案）

## 2. 目标用户

| 用户 | 特征 | 最关心的能力 |
| --- | --- | --- |
| 新手 RP 玩家 | 没配过 API、没写过角色卡 | 向导、教程、示例内容、一键开跑 |
| 有经验的 SillyTavern 用户 | 已有大量角色卡与世界书 | 资产导入、Prompt 引擎可控性、宏与变量、不被功能阉割 |
| TRPG 主持 / 玩家 | 需要掷骰、查规则、管角色卡 | 规则包、判定引擎、速查、骰点可追溯、时间线推进 |
| 内容创作者 | 产出世界、角色、剧情、配图 | 版本迭代、血缘管理、批量生成、导出分享 |

## 3. 产品原则

- **P1 简单易用优先**：默认路径不需要任何配置文件编辑；高级能力一律折叠进"高级"区。
- **P2 本地优先、数据可携带**：所有数据默认只存在本地；数据目录整体拷贝即可迁移。
- **P3 AI 是助手而非黑箱**：AI 的任何产出都是**提案（Proposal）**，必须经用户采纳或编辑才落库。
- **P4 渐进式复杂度**：第一屏只呈现最少信息；能力随使用深度逐步暴露。
- **P5 不破坏既有资产**：世界与角色版本**不可变**，存档引用具体版本号，迭代产生新版本而非覆盖。
- **P6 不重复造轮子**：复用 SillyTavern 的生态与数据格式，把"重写"限制在体验层。
- **P7 数据格式先于界面**：包格式与领域模型先冻结、可往返验证，再写 UI。
- **P8 时间与状态是显式的**：时间、角色状态、变量都是结构化数据，而不是模型叙述里的形容词。

## 4. 术语表

| 术语 | 含义 |
| --- | --- |
| World（世界） | 世界观设定卡，结构化字段 + 关联的世界书条目；有版本与血缘 |
| WorldBook（世界书 / Lorebook） | 关键词（可含时间等条件）触发的设定条目集合，命中后注入上下文 |
| Character（角色卡） | **统一的角色卡**，兼容 SillyTavern V2/V3 字段；创建时不区分身份 |
| 玩家角色（Player Character） | 会话中**被指定由用户操控**的那张角色卡；`{{user}}` 解析为它 |
| 卡司（Cast） | 会话中由 AI 扮演的角色卡集合 |
| 发言档案（Voice Profile） | 角色卡上的**发言欲望 / 发言能力**等属性，供发言调度器使用 |
| 发言调度器（Turn Scheduler） | 决定"这一轮谁发言、发言几条、顺序如何"的组件，模式可切换 |
| Visual Bible（视觉档案） | 角色的结构化外貌 / 服装 / 画风 / 参数设定，用于保证生图一致性 |
| Session（会话） | 一次扮演实例，绑定一组固定版本的世界 / 角色 / 预设 / 规则包 |
| Checkpoint（定点存档） | 会话中可回滚的节点：消息位置 + **时钟** + 变量 + 摘要 + 卡司状态 |
| Snapshot / 包（`.stpack`） | 可导出的分享容器，含设定、消息、状态、资源（见文档 04） |
| Proposal（提案） | AI 建议的变更（世界 / 角色 / 世界书 / 记忆 / 日程），需用户确认 |
| Lineage（血缘） | 世界或角色的版本继承关系与分叉来源 |
| RulePack（规则包） | 一套 TRPG 规则的数据化描述：角色卡模板、判定、随机表、速查条目 |
| 世界时钟（World Clock） | 世界内的历法与当前时刻，随会话推进并可回溯 |
| Agenda（日程） | NPC / 势力的计划事件清单，到点触发 |
| Stage（阶段） | 三段式流程中的一段：创建世界 / 创建角色 / 开始扮演 |

## 5. 核心流程

### 5.1 总览

```
   ┌──────────────┐    ┌──────────────┐    ┌──────────────────────────┐
   │  创建世界     │───▶│  创建角色     │───▶│        开始扮演           │
   │ Create World │    │    Create    │    │  Play（指定玩家角色 + 卡司）│
   └──────────────┘    │  Character   │    └──────────────────────────┘
          ▲            └──────────────┘                 │
          │                   ▲                         ▼
          │        ┌────────────────────────────────────────────┐
          └────────│  复盘迭代：Proposal → 新版本（含日程/时间线）  │
                   └────────────────────────────────────────────┘

   扮演内部循环：
   用户输入 / 发言调度 → AI 生成（流式） → 工具调用（掷骰 / 改状态 / 推进时间）
        → 状态与时钟更新 → 立绘切换 → 自动存档 → 下一轮
```

三个阶段互相解耦：世界和角色可以各自被多次复用，也可以在多次扮演之后**衍生出新版本**。
每一场扮演都绑定一组"冻结的版本快照"，因此迭代永远不会污染历史存档。

### 5.2 阶段一：创建世界（Create World）

**入口方式（四种，可混用）**

1. 空白创建：直接填写结构化表单
2. 模板创建：从内置 / 导入的世界模板出发
3. AI 共创：与 AI 对话，逐步完善世界观（推荐给新手）
4. 导入：导入 SillyTavern 世界书或他人分享的世界包

**世界卡结构（草案）**

| 分组 | 字段示例 |
| --- | --- |
| 基本 | 名称、题材/类型、时代背景、科技或魔法水平、视觉基调 |
| 地理 | 主要区域、城市、地标、气候、交通 |
| 势力 | 国家/组织、派系关系、权力结构 |
| 规则 | 超自然体系、力量来源、限制与代价、禁忌 |
| 叙事 | 核心冲突、当前局势、主题、情绪基调、叙事风格 |
| **时间** | **历法（年月日/时段名）、起始时刻、季节、一天的分段（晨/昼/昏/夜）** |
| 开场 | 开场钩子、初始场景建议、常见 NPC 类型 |
| 自定义 | 用户自定义字段（键值对，可增删） |

**AI 共创交互要求**

- 左侧对话，右侧实时预览世界卡；AI 每次产出以结构化补丁（JSON Patch）形式呈现
- 每个字段旁提供"让 AI 补全 / 重写 / 展开 / 精简"的局部操作
- 支持带**种子**的随机生成与"再抽一次"，结果可复现
- 支持**有限指示**生成：题材标签多选、必须包含 / 必须排除、篇幅档位、参考作品、
  一句话灵感等约束控件（"时间观"也应作为可约束项，如"慢节奏长线""一天之内"）
- 共创结束后可从对话中**抽取**世界书条目（提案形式，逐条采纳）

### 5.3 阶段二：创建角色（Create Character）

**前置**：选择一个世界（必选，AI 生成角色时作为上下文与约束来源）

**统一角色卡**：创建时**不区分玩家身份与卡司身份**。所有角色卡结构完全一致，
"谁由用户操控"在扮演开始时决定（见 5.4）。这样同一张卡既可以在 A 场扮演里当主角，
也可以在 B 场扮演里当 NPC。

**角色卡字段**：完整兼容 SillyTavern V2/V3 规范
（`name` / `description` / `personality` / `scenario` / `first_mes` / `mes_example` /
`creator_notes` / `system_prompt` / `post_history_instructions` / `alternate_greetings` /
`tags` / `creator` / `character_version`），并扩展 SmartTavern 自有字段：
**发言档案**、**视觉档案**、默认采样参数、语音、图标等。
自有字段一律写入 `extensions.smarttavern`，保证导出到 SillyTavern 时不丢兼容性。

**发言档案（Voice Profile）**

| 字段 | 含义 | 取值 |
| --- | --- | --- |
| `desire`（发言欲望） | 主动开口 / 接话的倾向强度 | 0–100 |
| `ability`（发言能力） | 在场景中能提供有效内容的分量（信息量、身份权能、行动力） | 0–100 |
| `roles`（发言角色标签） | 供规则匹配用，如 `冷静观察者`、`信息提供者`、`冲突制造者` | 字符串数组 |
| `maxLinesPerRound` | 单轮发言条数上限（防止话痨角色刷屏） | 1–5 |
| `cooldown` | 连续发言后的冷却轮数 | 0–3 |

发言档案支持**依据角色描述让 AI 自动评估生成**（提案形式），也支持用户手填。

**生成方式**：空白 / 模板 / AI 生成（随机或有限指示）/ AI 共创 / 导入

**视觉档案（Visual Bible）**：外貌结构化（发色发型、瞳色、体型、服装、配饰、显著特征）、
画风预设、负面提示、模型与采样参数、种子策略。视觉档案是生图一致性的唯一事实来源。

### 5.4 阶段三：开始扮演（Play）

**开局步骤**

1. 选择世界（指定版本）
2. 选择一张或多张角色卡（可从库中挑、也可当场新建）
3. **指定其中一张为玩家角色**（默认可自动推荐"你最近编辑过的卡"）
4. 其余角色自动组成**卡司**；卡司仍可由用户随时干预（见下）
5. 选择 Prompt 预设与规则包（可选，规则包用于 TRPG 场景）
6. 设定初始时钟（默认取世界卡的起始时刻）
7. **引入（Opening）**：手写 / AI 根据世界与角色生成 / 跳过
8. 进入扮演循环

**扮演界面要素**

- 消息流（流式、swipe 重生成、编辑、删除、继续写、回溯到此处）
- 发言者标识与轮次分组（一轮可以有多个角色发言）
- 输入区（多行、宏插入、快捷指令、OOC 括号）
- 立绘 / 颜绘区（随情绪标签自动切换，可手动覆盖）
- **常驻时钟**（当前年/月/日/时段）+ 时间推进按钮
- 状态栏（变量、HP / 理智 / 资源，由规则包或自定义模板定义）
- 骰子区（表达式、结果、历史、是否展示给 AI）
- 世界书命中提示（哪些条目被注入、为什么，**含时间条件命中**）
- 日程面板（待触发事件、倒计时）
- 存档按钮（新建定点存档 / 时间线 / 导出）
- 调试面板（本次请求的完整 prompt 与 token 用量）

**发言调度（Turn Scheduler）**

三种模式，由用户在会话设置中切换，随时可改：

| 模式 | 行为 |
| --- | --- |
| **用户全权** | 用户手动点"下一个谁说"，或用 `/say 角色名` 直接指派；AI 只负责写内容 |
| **自定义规则** | 按评分公式排序，允许用户编辑权重与阈值（默认公式见架构文档 5.6） |
| **AI 决定** | LLM 依据场景输出发言顺序与意图（提案形式，用户可一键覆盖） |

三种模式下共有的一致性保证：
- 每轮发言人数上限、单人条数上限、冷却轮数由本地调度器强制约束，**AI 不能突破**
- 被点名的角色获得权重加成；刚说过的角色获得衰减
- 玩家角色不参与排序（用户想说就说）
- 调度结果在 UI 上可见（谁来说、为什么），用户可随时插入、打断、跳过或静音某角色

**用户对卡司的干预（始终可用）**

- 直接编辑任意 AI 角色的发言内容
- 代写：以某角色的身份替它说一句，再交回 AI
- 临时接管 / 交还某个角色
- 禁言 / 解除禁言、把角色移出当前场景
- 强制某角色下一轮必须发言

**时间推进**

- 手动：`+1 时段`、`+1 小时`、`+1 天`、自定义
- 隐式：按会话设置每隔 N 轮自动推进一段（可关闭）
- AI 请求：模型可通过 `advance_time` 工具请求推进，是否自动接受由会话策略决定
- 任何时间推进都会：更新时间感知的世界书命中、检查日程表、写入自动存档
- 回退：时间随存档点回滚（时间不可单独回退，避免状态分裂）

**核心交互其余要求**：见第 6 节 F4。

### 5.5 迭代闭环（Iteration Loop）

1. 扮演告一段落（用户主动触发，或每 N 轮提醒一次）
2. 进入**复盘**界面：AI 分析本次扮演，提出变更提案
   - 世界：新增地区 / 势力变动 / 局势推进
   - 角色：关系变化、能力成长、状态变化（受伤、获得物品）
   - 世界书：新增或修订条目
   - 记忆：值得长期记住的事实
   - **时间线：发生了哪些日子、哪些事件已/将触发、日程是否需要顺延**
3. 用户逐条勾选、编辑、否决
4. 采纳的变更合并生成**新版本**，记录血缘与变更原因
5. 原会话仍绑定旧版本，可选择"以新版本继续"或"新建会话从该节点出发"

> 关键约束：迭代是**新增版本**，不是原地修改。这样历史存档永远可复现。

## 6. 功能需求清单

优先级：**P0** = MVP 必须；**P1** = V1 主要版本；**P2** = 后续演进。

### F1 模型接入与对话内核

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F1-1 | BYO-Key，多 Provider（OpenAI 兼容 / Anthropic / Gemini / Ollama / LM Studio / 自建网关） | P0 |
| F1-2 | 流式输出、停止生成、重生成、编辑消息、继续写 | P0 |
| F1-3 | 每个角色 / 每次会话可覆盖采样参数（temperature、top_p、max_tokens、惩罚项） | P0 |
| F1-4 | 失败可重试、可取消、错误可读（区分鉴权 / 限流 / 网络 / 内容审核） | P0 |

## 7. 原始需求的澄清与优化

### 7.1 「基于傻酒馆（SillyTavern）」

- **问题**：未明确是"改造 SillyTavern 本体"还是"兼容其生态"。
- **优化/决议**：**不 fork，兼容数据格式**——角色卡 V2/V3、世界书、Prompt 预设、
  `chat.jsonl` 可导入导出；SillyTavern 的 Chat Completion 后端**可选**作为一个 Provider 接入。
- **理由**：ST 前端是规模庞大的无框架单页实现，在其上重构 UI 的成本高于重写体验层，
  且上游迭代快、长期跟进成本高。
- **影响**：F9、F1-7、D1。

### 7.2 「多端运行」

- **优化/决议**：**Web / PWA（一等公民）→ 桌面（Tauri 2）→ 移动（响应式 PWA 优先）**；
  默认纯本地、无账号、不自动同步，同步为 V2 可选项。
- **影响**：F10、D3。

### 7.3 「定点存档」

- **优化/决议**：三层——**自动存档 / 定点存档（Checkpoint）/ 存档包（Snapshot）**；
  必须可回溯、可分叉。自 v0.2 起，Checkpoint **必须包含世界时钟**。
- **影响**：F4-7、F4-8、F4-11、F4-12、F11-3。

### 7.4 「存档导出」

- **优化/决议**：定义 `.stpack` 为标准包格式；**格式标准先于实现冻结**
  （见 `docs/04-分享格式规范.md`）；支持"仅设定 / 仅会话 / 全量"三档；
  ID 冲突重映射，绝不静默覆盖。
- **影响**：F4-9、F4-13、F9-4。

### 7.5 「利用 LLM 随机或有限指示生成世界观和角色」

- **优化/决议**：三种生成模式——**全随机（带种子）/ 约束随机（有限指示）/ 引导共创**；
  输出必须是可编辑的结构化卡片；统一走「提案 → 采纳 / 编辑 / 否决」。
- **影响**：F2-2~F2-5、F3-2、F3-3。

### 7.6 「生成立绘、颜绘、差分」

- **优化/决议**：以**视觉档案**为唯一事实来源；差分定义为**表情 × 服装 × 场景**矩阵；
  一致性策略分四级（固定种子 → 参考图 → 控制网/Reference → 专属 LoRA）；
  扮演中由情绪标签驱动切换。
- **影响**：F6 全部、D6。

### 7.7 「COC、DND、最终物语、赛博朋克的 TRPG 跑团和规则速查」

- **优化/决议**：拆成**规则内容 / 本地检索 / 判定引擎 / 跑团辅助 / AI 主持**五件事；
  首发只内置开放许可内容（如 D&D 5e SRD，CC-BY-4.0），其余靠用户导入；
  **骰点必须由本地引擎产生并回填给 AI**。
- **影响**：F7 全部、合规章节。

### 7.8 「多次扮演形成迭代后的世界观和角色卡」

- **优化/决议**：**不可变版本 + 血缘 + 提案合并**；扮演结束进入复盘，AI 提变更提案，
  用户勾选后生成**新版本**；旧存档永远指向旧版本，可复现。
- **影响**：F4-1、5.5、数据模型。

### 7.9 原始需求未提及但必需的部分（补充）

- **Prompt 预设与宏系统**：决定输出质量的核心可调项
- **世界书 / 分层记忆**：长会话不失控的前提
- **变量与状态**：TRPG、状态栏与时间系统的基础
- **成本控制**：模型分工、token 预算、缓存、用量面板
- **崩溃恢复**：长会话最容易丢数据，自动存档必须可靠
- **i18n**：中文社区是核心用户群，文案不得硬编码

### 7.10 本轮评审新增的三项优化

**（1）角色卡不再区分身份 —— 身份是会话的属性，不是卡片的属性**

- **原描述**：创建角色时区分"玩家身份"和"卡司身份"。
- **问题**：一张卡的身份应当随场景而变——同一个角色在 A 场扮演里是主角，在 B 场里可能是 NPC；
  创建期分叉会导致重复建卡、无法复用、导入导出复杂。
- **优化**：**统一角色卡**，创建期不分身份；**扮演开始时指定一张为玩家角色**，
  其余自动组成卡司；**用户对卡司的干预始终可用**（编辑发言、代写、临时接管、禁言、强制发言）。
- **影响**：F3-1、F4-2、F4-5；数据模型取消 `kind` 字段，`Persona` 集合不再需要。

**（2）发言调度系统 —— 把"谁来说话"从玄学变成可调参数**

- **原描述**：未提及，仅提到群聊。
- **优化**：为角色卡增加**发言档案**（发言欲望 / 发言能力 / 角色标签 / 单轮上限 / 冷却），
  用**可解释的本地评分**排序发言顺序；提供三种调度模式（用户全权 / 自定义规则 / AI 决定）；
  每轮人数、条数、冷却等硬约束由本地强制，AI 不能突破。
- **理由**：多角色场景最容易失控的地方是"话痨抢戏、配角沉默"，把它参数化后既可预期又可调优。
- **影响**：F3-4、F3-5、F4-6、F4-10、架构 5.6。

**（3）时间与日程 —— 提高优先级，纳入 MVP 基础**

- **原描述**：仅作为一个开放问题提出。
- **优化**：**基础部分（F11-1~F11-4）进入 MVP**：世界时钟、手动推进、时钟入存档、时间感知上下文；
  完整部分（隐式推进、AI 请求、日程表、倒计时、时间轴视图）进入 V1；历法与天气为后续。
- **理由**：时间是长线扮演与 TRPG 战役的骨架；事后补时间系统几乎等于重构存档、记忆与世界书，
  因此必须在数据模型第一版就纳入。
- **影响**：F2-6、F5-3、F11 全部、Checkpoint 结构。

## 8. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 桌面端首屏 < 2s；5000 条消息的会话滚动流畅（虚拟滚动）；图片懒加载 |
| 易用性 | 新用户 5 分钟内完成"世界 → 角色 → 第一轮对话"；核心流程零配置文件编辑 |
| 可移植 | 数据目录整体拷贝即可迁移；存档包跨端可读 |
| 隐私 | 数据只发送给用户显式选择的 Provider；密钥仅本地存储且不进入导出包 |
| 可靠性 | 所有 AI 调用可取消 / 重试；本地写入走事务，崩溃不损坏存档 |
| 可维护 | 引擎层与 UI 解耦；Provider / 规则包可插拔；schema 带版本与迁移 |
| 兼容 | 与 SillyTavern 往返导入导出不丢关键字段；包格式向后兼容 |
| 可解释 | 发言调度、世界书命中、时间推进、骰点结果都必须能说明"为什么" |
| 无障碍 | 键盘可完成主要操作；对比度符合 WCAG AA |

## 9. MVP 验收标准

1. 全新用户按向导即可配置 Provider 并成功发出一轮对话。
2. 从内置示例世界出发，用 AI 共创在 5 分钟内得到一个可用的世界卡（含历法设定）。
